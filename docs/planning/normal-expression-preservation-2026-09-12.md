# 정상 표현 보존 수정과 실제 게시판 대조

2026-09-12. 현재 `codex/desktop-local-storage`의 미커밋 변경을 보존하며 공통 검사기만 수정했다. UI 방향, Enter/Shift+Enter, 웹·Windows·macOS 공유 구조는 유지한다. 원문은 Git에서 제외되는 `local-corpora/reports/normal-preservation-2026-09-12/`에 보관한다.

## 변경과 완료 기준

1. 명사와 이름에 편집 거리가 가깝다는 이유만으로 수정 후보를 주던 경로를 제거했다. 미등록 안내·건너뛰기·개인 사전 등록은 유지한다. 검증된 표기 규칙과 전체 활용 검증을 통과한 어미 수정은 유지한다.
2. `아니-`, 단일어의 보조 용언 결합, 명사 파생 용도 표현, 의도·전언 어미를 보완했다. 단일어 세 음절을 무조건 합성어로 보지 않는다. 장음절 동사의 구성을 모르면 필수 띄어쓰기 후보를 내지 않는다. 현재 보존·합성어 판별 목록은 제한적이며 한국어 전체 파생 분석기가 아니다.
3. 미등록 조각, 의태어/반복 표현, 접미 표현과 용언의 동형성, 어미 조각 때문에 단어 내부를 나누는 경로를 제한했다. 검증된 조사 경계와 의존 명사 규칙을 보존해 등록어 주변 오류까지 감추지 않는다.
4. 기존에 유사도에서만 나오던 맞춤법·전셋집 표기는 범위가 제한된 자체 규칙으로 옮겼다. 새 배포 사전·모델·라이브러리는 도입하지 않았다.

이번 수정의 완료 기준은 확인한 훼손 후보 차단, 정상 활용 변형에 대한 회귀 시험, 주변 실제 오류의 후보 유지, 개인 사전 분리, 편집기 수정·되돌리기·저장 확인이다. 전체 한국어 품질 목표의 완료를 의미하지 않는다.

## 클리앙 표본과 독립성

Chrome에서 8개 글의 본문 전체를 직접 읽었다. 댓글·이미지는 제외하고 빈 줄만 정리해 분석했다. 테스트 자료에 원문을 공개 편입하지 않았다.

- 개발에 사용: [기기 구매](https://www.clien.net/service/board/park/19262464), [타이핑 경험](https://www.clien.net/service/board/park/19262457), [달리기](https://www.clien.net/service/board/park/19262433), [휴대폰 비교](https://www.clien.net/service/board/park/19262446), [식사 경험](https://www.clien.net/service/board/park/19262437), [구매 고민](https://www.clien.net/service/board/park/19262455), [게임 경험](https://www.clien.net/service/board/park/19262444).
- 별도 대조: [로그인 알림 경험](https://www.clien.net/service/board/park/19262459). 수정본을 파일로 고정한 뒤 읽고, 보호할 정상 표현과 검토 지점을 예측 전에 기록했다. 본문 153자에서 띄어쓰기 후보 5개와 미등록 안내 2개가 나왔다. 검토한 정상 표현을 바꾸는 후보는 없었다. 그 뒤 코드 검토로 보조 용언 판별을 좁혔으며, 최종 파일로 재검사한 전체 결과도 동일했다. 이 글의 결과로 규칙을 수정하지 않았다.

중간에 별도 표본으로 읽었다가 문제가 나와 고친 글은 모두 개발 자료로 전환했다. 한 편의 별도 대조는 제한된 진단이며 정확도·완전한 독립 평가 통과의 증거가 아니다. 원래의 4,206행 보류 자료는 예측하지 않았고 미판정 자료를 정답으로 사용하지 않았다.

## 개발 70개 글 전수 비교와 손실

기존 개발 70글의 제목·본문 140필드를 모두 재검사했다. 기존 보류 30글은 제외했다.

| 안내 종류 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 맞춤법 후보 | 87 | 58 |
| 띄어쓰기 후보 | 372 | 363 |
| 후보 없는 미등록 | 617 | 655 |

25필드가 달라졌다. 기존 적용 가능 안내 40개가 없어지거나 바뀌고 새 경계 후보 2개가 생겼다. 이 수치는 정확도가 아니다. 정상 고유명사·활용형을 다른 단어로 바꾸는 후보가 제거됐지만, 유사도에만 의존하던 오타 후보와 일부 유효한 띄어쓰기 후보도 줄었다. 선샘님/티이어 유형, 많이해서/못하는건가요 유형 등은 검출 손실로 남겼다. 공개 원문을 새 사전에 자동 등록하지 않았다.

남은 과제는 정상 활용형의 미등록 부담, 실제 오타에 대한 근거 있는 후보 확장, 의존 명사·문장 간 복합 오류의 누락이다. 미등록 분석의 조사 추정도 이름의 마지막 글자를 조사로 해석할 수 있다. 실제 UI 시험에서는 기본 단어 입력을 작성자가 고쳐 이름 전체를 등록할 수 있음을 검증했다.

## 검증

- Node 단위 시험 163개, Vitest 145개 통과. 새 정상 보존 시험은 9개이며 기존 유사도 시험의 기대값은 바뀐 정책(미등록 검토)으로 명시적으로 수정했다.
- TypeScript 검사 통과. 배포 데이터 2개 및 원 라이선스 고지 해시 검사 통과(MIT/Apache-2.0 범위). 언어 품질의 인증은 아니다.
- Chrome 실제 공통 편집기: 정상 표현 4개와 실제 오타를 함께 입력 → 오타만 후보 → Shift+Enter → 정상 표현 유지 → 되돌리기로 원문 복원.
- 본 앱의 Chrome 연결은 탭 연결 오류가 반복돼 직접 검증은 임베디드 공통 편집기를 사용했다. 임베디드 예제에는 저장이 연결되어 있지 않다. 본 앱 저장·재열기는 별도 Chromium/설치된 Chrome 자동화 시험으로 검증한다.
- 기본 Playwright 브라우저 실행 및 샌드박스 내 설치 Chrome 실행이 실패했다. 기존 설치 Chrome을 임시 테스트 프로필로 권한 확장 실행해 검사했다. pnpm도 자동 설치 확인 단계에서 실패하여 설치된 Node 시험 진입점을 직접 사용했다. 의존성 설치나 교체는 하지 않았다.
- 최종 설치 Chrome E2E 37개가 59.0초에 통과했다. 본 앱 수정·되돌리기·저장·재열기와 개인 사전 검증을 포함한다. 실물 Windows·macOS 앱, 물리 IME 입력, 기기 간 동기화는 이번 검증 범위가 아니다.
- 별도 클리앙 본문도 Chrome 임베디드 편집기에 그대로 입력했다. 사이트명을 이번 검사에서 모두 건너뛰고 띄어쓰기 5개를 적용한 뒤 원문 대조 결과 선택 공백 외 변경이 없었다. 마지막 수정의 되돌리기도 확인했다.

## 재현과 다음 실행

비공개 보고서 폴더의 `before/`는 착수 시 코드, `release-candidate/`는 별도 원문을 읽기 전 코드다. `development-survey.mjs`는 개발 70개 비교, `compare.mjs`는 신규 개발 문장 비교, `release-eval.mjs`는 별도 원문의 고정 코드 평가다. 각 입력에 원문 링크·검사 전 검토 기록·완전한 정답 여부를 남겼다.

다음 실행 프롬프트: 지원은 실시간으로 보고 있지 않다. 이 보고서와 최신 git diff에서 시작해 현재 UI와 개인 사전 동작을 유지하며 정상 표현 보존·검출 손실을 함께 개선하라. 개발로 전환한 7개 클리앙 글을 보류 평가로 재사용하지 말라. 로컬 조사·가역 구현·검증을 이어가되 원격 쓰기·새 의존성·배포·유료 사용은 승인 범위에 없다. 새로운 독립 표본의 판정과 후보 동결을 먼저 기록하고, 정상어와 이름에 대한 유사도 치환을 부활시키지 말라. 전체 품질 목표의 200 정상/200 오류 이상 및 정밀도 목표를 소규모 회귀 시험으로 대체하지 말라.
