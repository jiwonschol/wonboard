# 인터넷 게시글 교정 제안의 수정 전후 비교

새 평가 자료 173개에서 명백한 오교정은 16개에서 9개로 줄었지만, 한국어의 주석된 필수 수정 20개를 추가로 놓치고 1개만 새로 잡았다. 영어 오교정 7개는 그대로다. **이번 후보를 인터넷 글 교정 품질이 개선된 완성본으로 판정하지 않는다.** 일반 띄어쓰기 제안을 넓게 억제한 부분을 더 정밀하게 고쳐야 한다.

이 보고서는 실제 공개 글을 개발에 사용한 자료와 새 평가 자료로 나누어, 잘못된 수정 제안과 필요한 수정의 누락을 함께 비교한다. 이전에 본 151개는 개발 자료다. 새 평가 자료의 결과를 보고 이번 후보 코드를 다시 조정하지 않았다. 코드와 보고서는 로컬 실험 브랜치에 보존하며 원격 반영·배포하지 않았다.

## 변경과 평가 방법

한국어에서는 조사 `한테는`, 용언 어미와 의존 명사, 인명 앞의 호칭을 고려하고, 사전에 있는 조각으로 나눌 수 있다는 이유만으로 띄어쓰기를 제안하던 경로를 제한했다. 각 경계에 조사·용언·보조 용언 같은 문법적 근거가 있어야 한다. 영어에서는 축약형의 대문자·아포스트로피를 보존하고, 약어·식별자를 비슷하게 생긴 일반 단어로 바꾸는 제안을 줄였다.

수정 후보의 코드·사전·평가 파일 13개는 2026년 9월 27일 19:02 KST에 고정했다. 그 뒤 부모 에이전트가 예비·신규 자료의 원문과 라벨을 검토했다. 앞서 고정한 후보 1도 보관하며, 현재 후보 2와의 차이는 개발 자료에서 확인한 의문형 어미 처리다. 신규 자료의 예측으로 후보를 조정하지 않았다.

원격 Luna가 검사기 예측을 보지 않고 최소 수정 구간과 허용 대안을 주석한다. 부모 에이전트가 예측 전에 형식·누락·허용형을 보강하고, 최초 예측 이후에는 제안별 오교정을 별도 판정한다. 독립 언어 전문가의 정답은 아니다. 라벨이 완전하지 않은 글은 보류로 표시하고, 공지·홍보·인용·약관은 일반 게시글 분모와 구분한다.

같은 발췌문을 수정 전·후 검사기에 각각 한 번 입력한다. 입력·라벨·검사기 해시와 첫 예측을 보존한다. `필수 수정 도달`은 모델이 주석한 구간을 첫 후보의 수정으로 만들 수 있는지를 뜻한다. 전체 언어 오류의 재현율이 아니며, 다른 잘못된 제안을 사용자가 무시할 수 있다는 가정이 있다. 실제 오교정 수는 정상 라벨과의 불일치 수를 대신 쓰지 않고, 오류가 있는 글까지 포함하여 모든 첫 제안을 검토해 센다.

## 새 평가 자료와 수집 한계

총 173개는 신규 수집 126개와 미노출 보관 자료 47개다. 한국어 신규 자료는 오르비 30개·퀘이사존 30개이며, 기존 공개 목록의 다음 후보에서 보관한 한국어 47개는 보배드림 11개·오르비 12개·퀘이사존 12개·개드립 12개다. 이 47개도 후보 코드 고정 전에는 부모·판정 모델에게 원문을 노출하지 않았다.

신규 한국어는 저장한 공개 목록 후보를 시드 해시 순서로 추첨했다. 영어는 Reddit 35개와 Hacker News Ask 31개다. 영어의 제목 발췌는 9개, 본문 발췌는 57개이며 **도구가 노출한 부분 후보 집합을 전수 추출한 자료**다. 해시 정렬은 했지만 무작위 추출로 부르지 않는다. Reddit은 12개 하위 게시판에 걸치며 Hacker News는 기술 주제에 편중되어 있다.

언어별 신규 150개 목표에는 못 미쳤다. 한국어 출처는 앞 회차의 [와플보드 순위](https://waffleboard.io/ranking) 기반 목록을 이어 사용했으나, 보배드림은 406, 82쿡은 연결 거부, NBA매니아는 429, PGR21은 접근 챌린지로 추가 확보에 실패했다. 개드립의 이번 응답에서는 게시글 상세 링크를 추출하지 못했다. 접근 제한을 우회하지 않았다. 한국어 신규 60개를 두 출처에서 얻었다는 편중을 숨기지 않는다.

발췌는 게시글별 최대 25개 공백 구분 단어다. 이전 개발 자료 211개와 이미 노출된 영어 추가 7개를 URL 및 공백 정규화 발췌문으로 대조했다. 영어 후보 71개 중 기존 노출 자료와 겹친 5개를 별도 보존하고 제외했다. 한국어 투표 UI 혼입과 영어 API HTML entity 미복원도 예측 전에 수정했으며 수정 전 자료를 보존했다.

입력과 라벨은 19:27 KST에 고정했고, 173개 모두 원문 구간·중복·스키마 검증을 통과한 뒤 두 검사기의 첫 예측을 저장했다. 이 검증은 라벨의 언어학적 완전성을 증명하지 않는다. Luna 초벌에는 다른 글의 표현 혼입, 대문자·조사·띄어쓰기 누락, 허용형의 과교정이 있었고 부모의 보강을 거쳤다.

### 출처 분류의 사후 정정

첫 라벨은 짧은 질문·웃음·부품 목록 5개를 평가 부적합으로, 짧은 인용을 포함한 사용자 질문 1개를 인용문으로 분류했다. 인터넷 글을 검사한다는 목적상 이 6개도 일반 사용자 글에 포함해야 하므로, **예측 이후 분류만 정정한 별도 집계**를 만들었다. 최초 입력·라벨·예측·집계는 그대로 보존했다. 최종 일반 글 분모는 한국어 102개와 영어 66개, 합계 168개다. 나머지 5개는 공지 1개·홍보 3개·약관 1개다. 아래 전체 173개 오교정 집계에는 이 구분과 관계없이 모두 포함한다.

## 처음 보는 글에서의 수정 전후 결과

두 검사기의 서로 다른 첫 교정 제안 165개를 전부 검토했다. 같은 구간·같은 제안이 두 검사기에 있으면 한 번 판단하여 양쪽에 적용했다. 기존 오류를 일부 남긴 제안과 새로 잘못된 경계·단어를 만드는 제안을 구분했다. `조사받고`, `검수 받으려고`, `메인컴`, `post-op`의 표기 판단 4개는 보류해 명백한 오교정 수에 넣지 않았다. 독립 전문가 검수가 아닌 부모 모델의 사후 판정이다.

| 평가 자료 | 글 수 | 수정 전 명백한 오교정 | 수정 후 명백한 오교정 |
| --- | ---: | ---: | ---: |
| 보관 한국어 | 47 | 1 | 0 |
| 새 한국어 | 60 | 8 | 2 |
| 새 영어 | 66 | 7 | 7 |
| 전체 | 173 | 16 | 9 |

전체 첫 제안은 164개에서 132개로 줄었다. 오교정이 하나 이상 있는 글은 15개에서 8개로 줄었다. 일반 사용자 글 168개만 보면 오교정은 15개에서 9개, 해당 글은 14개에서 8개다. 이 비율을 인터넷 전체의 오류율로 일반화하지 않는다.

수정 전의 `풀집중해야 → 풀집 중 해야`, `해야지의 → 해야 지의`, `경제관념챙겨야하는데 → 경제 관념 챙겨 야하는데`, `NVMe → name`은 사라졌다. `감동받아서 → 감동 받아서`도 사라졌다. `감동받다`의 붙임은 [국립국어원 답변](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=90&pageIndex=1&qna_seq=328615)을 확인했다.

그러나 `gemini → geminy`, `제미나이로 → 제미나 이로`, `didnt → didst`, `unspaced → unscaled`, `scratch.mit.edu` 내부의 `mit → mitt`와 `edu → ed`가 남았다. 실제 패키지 이름인 `micropip`도 `microbic`으로 바꾼다. 이름은 [프로젝트 공식 문서](https://micropip.pyodide.org/en/latest/index.html)로 확인했다. 이는 특정 예전 사례 19개를 없애도 새로운 이름·도메인·일반 단어에서 같은 종류의 실패가 발생함을 보여 준다.

| 일반 사용자 글의 잠정 라벨 기준 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 한국어 필수 수정 구간 도달 | 112 / 220 | 93 / 220 |
| 한국어 주석 수정을 모두 만들 수 있는 글 | 20 / 54 | 15 / 54 |
| 한국어 미등록 검토 알림 | 271 | 301 |
| 영어 필수 수정 구간 도달 | 1 / 9 | 1 / 9 |
| 영어 주석 수정을 모두 만들 수 있는 글 | 0 / 7 | 0 / 7 |
| 영어 미등록 검토 알림 | 27 | 27 |

한국어에서 `걷다보니`, `점심먹으러`, `되신걸까`, `맞출겸`, `나올수도`, `변별할수도`, `심상치않아보임` 등 이전에 고치던 20개 구간을 놓쳤다. 새로 잡은 것은 `하려했습니다 → 하려 했습니다` 1개다. 미등록 알림도 늘었으므로 제안이 사라진 것을 곧 정상 인식으로 해석하면 안 된다.

**다음 우선순위는 추가 수집량 확대보다 검사기 수정이다.** 이름·도메인·기술 식별자를 보호하고, 영어 후보의 문맥 적합성을 제한하며, 한국어에서 확인된 문법 경계까지 막아 버린 억제를 좁혀야 한다. 이번 173개는 이제 개발 자료로 전환되므로 이후 여기에 맞춰 고친 점수를 독립 평가로 재사용하지 않는다. 다음 후보는 별도 시기·출처의 미노출 자료에서 다시 비교해야 한다. 현재 결과로 실전 품질 통과나 전체 정확도 향상을 주장하지 않는다.

## 개발 자료의 결과

앞서 확인한 파괴적인 첫 제안 19개는 이번 후보에서 모두 사라졌다. 이는 해당 제안이 사라졌다는 뜻이며, 미등록 알림까지 사라졌거나 모든 오류를 올바르게 고쳤다는 뜻은 아니다. 예를 들어 `증상나타남`은 잘못 나누는 제안 대신 미등록 검토 대상으로 남는다.

| 개발 자료의 일반 글 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 한국어 주석 필수 수정 구간 도달 | 105 / 207 | 99 / 207 |
| 한국어 주석된 수정을 모두 만들 수 있는 글 | 10 / 47 | 11 / 47 |
| 영어 주석 필수 수정 구간 도달 | 1 / 11 | 4 / 11 |
| 영어 주석된 수정을 모두 만들 수 있는 글 | 1 / 8 | 2 / 8 |

한국어에서 이전에 잡던 8개를 놓치고 2개를 새로 잡았다. `병원갔더니`·`시비걸어놓고` 같은 올바른 분리까지 보수적인 제한에 걸리는 비용이 있다. 이 개발 자료의 결과만으로 일반적인 개선을 주장하지 않는다.

## 검증과 보존

관련 Node 단위 테스트 122개, 문서 모델 Vitest 테스트 4개가 통과했다. 새 회귀 테스트는 정상 조사·연결 어미·이름의 잘못된 분리, 유효한 문법 경계의 보존, 영어 축약형·식별자와 실제 오타를 확인한다. 최초 문서 테스트를 Node 러너로 직접 실행한 것은 러너 선택 오류로 실패했고, 해당 프로젝트의 Vitest로 다시 실행해 통과했다.

로컬 LLM은 실행하지 않았다. 로컬에서는 공개 HTML·API 응답 파싱과 짧은 JavaScript 비교만 수행했다. 수정 전·후 검사기 초기화는 각각 733ms·712ms, 173개 검사는 231ms·238ms, 종료 시 RSS는 약 338MiB·342MiB였다. 이는 최고 메모리나 전체 수집 자원량이 아니다. 이번 범위에서 전체 빌드·UI·E2E·배포 검증은 하지 않았다.

원문·라벨·목록·접근 실패·스냅샷·예측·제안별 판정은 Git 제외 경로 `local-corpora/live-round2-2026-09-27/`에 보존한다. `protocol.json`, `baseline-freeze.json`, `candidate-freeze.json`, `evaluation-freeze.json`, `paired-model-comparison.json`이 최초 결과다. 출처 분류 정정은 `source-eligibility-postprediction-review.json`, 정정 집계는 `paired-model-comparison.source-reviewed.json`, 모든 첫 제안의 판정은 `destructive-suggestion-paired-audit.json`에 있다. 이전 회차의 원본과 첫 예측은 수정하지 않았다.
