## 실행 순서

1. 출처 감사: 고정 revision·원본 해시·품사·선별 조건·배포 고지·별도 조건을 확인한다. 사전 크기뿐 아니라 정상어/오타/인터넷어가 어떤 집합에 들어 있는지 추적한다.
2. 비교 실험: 현재 방식, 사전 인식 순서 변경, 품사·활용 보강, Nori 분석 경로를 각각 분리한다. Nori는 Java 구현이며 현재 Java가 없다. 읽기와 소스 비교는 계속 진행하고, 실제 실행을 못 하면 미실행으로 남긴다. 설치할 런타임은 제품에 무조건 탑재하지 않는다.
3. 판정 보강: 정상 표현 보존, 철자 오타, 띄어쓰기, 미등록어, 문맥 혼동을 분리한다. 의심 항목만 라벨링하면 누락률을 계산할 수 없으므로 전체 문장에서 기대 결과를 판정한다. 모호한 항목은 점수 분모에서 조용히 빼지 말고 별도 개수로 보고한다. 공개 시험은 직접 작성한 예제로 만들며 PGR 원문을 커밋하지 않는다.
4. 구현: 인식·분절·후보 생성/정렬·문맥 규칙을 구분한다. 실전 오탐을 줄이는 수정부터 적용하되 모든 항목을 unknown으로 바꿔 점수를 올리지 않는다. 정답표 문자열을 런타임 예외 목록으로 복사하지 않는다.
5. 측정: 같은 개발 정답에서 기준과 변경본을 비교한다. 문장별 거짓 수정 제안, 수정안 정확도와 검출률, 미등록 안내/사전 등록, 문맥 사례를 따로 보고한다. 최종 후보를 고정한 후 보류 30개를 한 번 평가한다. 보류를 보고 수정하면 그 표본을 이후 독립 검증이라고 부르지 않고 새 표본을 확보한다.
6. 통합: Node 회귀, 타입 검사, 웹 Worker, 실제 UI에서 선택→바꾸기→undo/redo→저장/재실행, 한영 혼용과 한글 조합 입력을 검증한다. 실제 OS 입력을 모의 시험으로 대체하지 않는다. 새 사전 크기·초기화·1만 자 검사 지연·메모리를 측정한다.

정상 문장의 허용 띄어쓰기 대안도 예측 전에 명시한다. 허용 대안을 제안한 것은 원문 훼손으로 세지 않으며, 첫 후보 외에 표시된 모든 잘못된 후보는 오제안에 포함한다. 이 기준을 위해 평가기의 normal 행에 optional 대안을 허용하되 필수 오류/미등록/보호 범위는 계속 금지한다.

후보 품질 목표: 충분히 판정된 독립 시험에서 첫 수정안 정확도 98% 이상, 오류 구간의 허용 후보 상위3 포함 95% 이상, 정상 문장에 잘못된 수정 제안을 내는 비율 1% 이하. 철자/띄어쓰기/문맥 각각 표본 수와 분모를 명시한다. 최소 200개 오류 구간과 200개 정상 문장이 없으면 통과가 아니라 작은 표본의 예비 결과다. 미등록 안내 대상 검출률 95% 이상을 별도 측정한다. 수치가 부족하면 실패를 기록하고 승인 범위에서 개선한다. 일반 한국어 전체 성능으로 확대 해석하지 않는다.

위 수치는 목표이지 현재 성능이 아니다. 원칙상 허용된 표기를 바꾸는 후보는 강제 교정 오류와 구분하되 불필요한 경고량에도 집계한다. 문맥이 불충분하면 확정 정답을 만들지 않는다. 성능 목표는 기존 계획의 Worker 압축 2MB 상한과 1만 자 warm 검사 500ms 이내를 우선 적용하고, 실제 환경·최대값을 남긴다. 목표를 바꾸려면 근거를 보고하며 실패를 숨기기 위해 완화하지 않는다.

### 이어서 실행할 프롬프트

### Nori 실측 비교

Lucene Nori 9.12.3을 Temurin 21.0.12.1+1의 임시 실행 환경에서 실행했다. 시스템 Java 설치나 제품 의존성 변경은 없다. Java 아카이브의 SHA256은 Adoptium API 응답과 일치했다. 19개 진단 문자열과 개발 70개 글의 제목/본문을 DecompoundMode.NONE, POS 필터 없음, 사용자 사전 없음으로 분석했다. JVM 시작을 포함한 단일 실행 약 533ms는 원보드 브라우저 성능과 직접 비교하지 않는다. 보류 표본은 미사용이다.

Nori는 해치우고를 해치우/VV+고/E로 분석하지만 메세지를 NNG, 부딛히면을 부딛히/VV+면/E로 분석한다. 만들는도 VV+E이며 올바른 활용 여부를 보증하지 않는다. 질게는 VV~E로 해석되므로 인터넷 용어 검출을 형태소 인식 여부에만 맡길 수 없다. 현제/현재 모두 NNG이며 문맥 판정 없이 한쪽을 오타로 확정할 수 없다. Nori는 형태 분석 비교에 활용하고 표준 표기 검사 대체로 채택하지 않는다. 새로운 정답 사전으로 간주하거나 분석 결과를 그대로 배포 자료에 넣지 않는다.

비교 스크립트 local-corpora/compare-nori.mjs, 로컬 Java 소스 local-corpora/NoriProbe.java, 결과 reports/nori-comparison.json에 입력/분석 결과와 JAR 해시를 기록했다. 실행 환경은 /private/tmp/wonboard-nori-r3wfyF 이며 임시 디렉터리 소멸 시 재구성이 필요하다. 제품 코드·사전에는 Nori/JDK를 추가하지 않았다. 다음은 기등록 비표준 표기와 정상 활용을 구분할 자체 표기 규칙/어휘 출처 정리이며, Nori가 정상 판정을 보장한다는 가정은 사용하지 않는다.

### 조사 결합 오타 후보 수정

후보 활용 검증: 근접 철자 후보 뒤에 조사/어미를 결합할 때 최종 표면형도 인식되는지 확인하도록 수정했다. 해치운고/해치울고/해치워고처럼 활용형을 어간으로 다시 쓰던 후보를 제거했다. 해치우고 자체는 아직 unknown일 수 있으므로 이를 정상어 인식 성공으로 보고하지 않는다. 개발 baseline 대비 거절 출력 변경 92건, 허용 후보 손실 0, 새 출력 10건. 기존 전체 오류 352건 중 정확히 92건을 해결했다고 해석하지 않는다(후보 목록 변경 포함). 형태 테스트 26개 통과. 다음에는 규칙 개선으로 바뀐 unknown 안내의 품질과 정상어 누락을 별도로 평가해야 한다.

현재 혼동 문맥: 현제 직장에서 등 현재 시점을 의도한 문장에 현재 후보를 추가했다. 현재/현제 자체의 어휘 구별은 공식 표제어와 한국학 자료로 확인했고, 뒤따르는 직장/상태/사용 등의 단서 선정은 자체 휴리스틱으로 명시한다. 인용/사용자 사전/아우 문맥 및 개행 보호를 시험했다. 단독 현제의 뜻은 미판정으로 두며 일반 한국어 문맥 이해로 확대하지 않는다. 개발 baseline 대비 거절 출력 변경 75건, 허용 후보 손실 0, 새 출력 8건. 이는 누락 전체를 판정한 재현율이 아니다. 문맥 테스트 3개와 타입 검사 통과.

두 글자 후보 격리 실험: root.length>=3을 >=2로 바꾸면 개발 70개에서 결과가 165곳 변했다. 테란→토란, 갈축→가축, 질게→지게 같은 오제안이 포함되어 채택하지 않았다. local-corpora/compare-short-words.mjs 및 reports/short-word-experiment.json에 보존했다. 짧은 단어 검출은 여전히 미완료이며 단순 편집 거리 확대를 성능 개선으로 간주하지 않는다. 제품의 추측 분절보다 철자 후보를 우선하는 경로에는 전체 단어의 기존 인식 여부를 추가 확인하도록 보완했다. 향후 짧은 후보 보강 시 정상 인식을 덮어쓰지 않도록 하는 조건이다.

명사 활용 연결 보강: 등록 명사+서술격 활용(인/인데요/이었던 등)을 사전 분석으로 연결하고 -적 파생형과 이기+보조사 일부를 인식한다. 개인적인/질문인데요/상황이었는데를 잘못 띄우던 원인을 수정했다. 해본적이 누락 회귀가 생겨 의존 명사 적의 규칙을 파생 접미사와 분리했고, 구체적이긴/친화적이기도 신규 오탐도 보완했다. 마지막 관련 형태 테스트 25개와 타입 검사 통과. 직전 전체 Node 39개 통과. 현재 단계의 새 형태 변화는 실제 UI를 다시 실행하지 않았으므로 앞선 UI 결과와 구분한다. 넓어진 파생 인식의 미등록어 손실과 문맥 동음이의성은 아직 검증할 범위로 남긴다.

실제 UI 검증: Chromium에서 기존 spelling.spec.ts 11개와 새 명사/어간 수정안 적용 시험 1개를 통과했다. 새 후보 메시지를/타이어를/재테크는/부딪히면을 선택 후 Change로 적용하고 재로드 저장까지 확인했다. 기존 시험은 undo/redo, 사용자 사전, Worker 종료, stale 문서 보호, 한국어/영어 390px 경계와 콘솔 오류를 포함한다. 최초 실행에서는 나으세요를 교정 후 unknown으로 다시 띄우는 회귀가 드러났고, 사전이 증명하는 ㅅ 탈락 표면형에 -으- 결합을 허용하여 해결했다. Browser 전용 스킬이 없어 저장소 Playwright 경로로 실행했으며 실제 물리 IME, macOS 앱, Firefox/WebKit은 이번 실행에 포함하지 않았다. 스크린샷 /private/tmp/wonboard-spelling-new-corrections.png 및 wonboard-spelling-ko-390.png를 직접 확인했다. 전체 목표는 여전히 미완료다.
