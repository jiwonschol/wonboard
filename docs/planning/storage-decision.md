# 후속 결정: 일반 사용자가 소유·관리하는 저장소와 오래 유지되는 이미지 주소

2026-09-05. **결정 보류. 이 문서는 공급자 채택이나 구현 승인이 아니다.** 오늘 작성기 구현을 PR로 보존하고, 공개 이미지 제공 방식은 지원이 다시 판단한 뒤 진행한다.

후속 논의: [GitHub 이슈 #1](https://github.com/jiwonschol/wonboard/issues/1). 이후 결정과 사업자 검증은 이 이슈에서 이어간다.

## 해결하려는 사용자 문제

Wonboard는 사람이 글과 사진을 편하게 작성하고, 원하는 커뮤니티로 내보내는 도구다. 사용자는 개발자가 아니며 NAS, 도메인, 클라우드 관리 지식을 갖췄다고 가정할 수 없다. 이메일 대용량 첨부처럼 일정 기간 후 내려받을 수 없게 되는 경험을 반복하지 않고, 몇 년 뒤에도 게시글의 사진을 보고 싶어 한다. 메일 서비스별 만료 일수는 다르므로 특정 일수를 일반화하지 않는다.

지원이 원하는 것은 **사용자가 자기 계정으로 파일을 관리하고 책임과 권한을 갖는 저장소**다. 무료만이 절대 조건인지, 소액 유료 구독을 수용하는지는 미결정이다. Wonboard가 모든 사용자의 사진을 보관·중계하고 장기 서비스 운영까지 떠안는 대형 플랫폼이 되는 것은 목표가 아니다. 단순한 최저가 비교로 결론 내리지 않는다.

Google 계정의 보편성이 Drive를 먼저 검토한 이유다. Google Drive와 Google Cloud Storage는 별도 제품이며, 일반 Google 계정을 갖고 있다는 사실만으로 개발자용 클라우드의 설정·과금·공개 주소 문제가 해결되는 것은 아니다. 다음 조사에서는 두 제품을 구분한다.

## 현재 구현과 오늘의 기술 검증

- Client는 브라우저에 문서와 원본 사진을 보관한다. 사진 배치·크기 조절·임시저장·ZIP 백업은 공개 호스팅 없이 가능하다.
- 외부 게시판 독자에게 사진을 보여주려면 로그인 없이 이미지를 제공하는 곳이 필요하다. Core 설치는 가능한 경로 중 하나이며 Client의 필수 조건으로 확정하지 않았다.
- 현재 Google OAuth, 실제 저장소 자동 업로드, 운영용 공개 이미지 서버, 공개 HTML 내보내기는 미구현이다.
- 승인된 합성 PNG 한 장을 수동으로 Drive에 올리고 링크 공개한 시험에서, 인증 없는 원본 다운로드와 원본 해시 일치를 확인했다. 같은 다운로드 주소의 Chrome `<img>` 직접 삽입은 `net::ERR_BLOCKED_BY_ORB`로 실패했고, 로컬 서버가 원본을 받아 전달하면 640×360 이미지 표시가 성공했다.
- 이는 한 파일의 기술 가능성 검증이다. 모든 Drive 주소가 실패한다는 증명, 공식 장기 호스팅 지원, OAuth 자동 업로드, 실제 커뮤니티 게시, 부하 또는 5년 보존 검증은 아니다. 세부 관측은 `web-first-plan.md`에 보존한다.

| Wonboard Core 자체 호스팅 | 설치형 게시판이 파일 제공까지 맡는 제품 방향 | NAS·호스팅 없는 Client 사용자에게 필수로 요구할지 미결정. 기존 서버·프리셋 계획을 삭제한 것이 아님 |

### 2026-09-05 공식 확인 출처

- [ImgBB API](https://api.imgbb.com/): API 키로 업로드하며 자동 삭제 기한은 선택 항목. 기한 미설정이 영구 보존 보증은 아니다.
- [ImgBB 요금표](https://imgbb.com/): Pro 기능으로 API Access를 기재한다. 앞선 추천에서 API 문서만으로 무료 연결 가능성을 높게 본 판단을 수정한다. 무료 계정 시험이나 사업자 답변 없이 '유료 회원만 가능'도 확정하지 않는다.
- [ImgBB 공식 플러그인](https://imgbb.com/plugin) / [약관](https://imgbb.com/tos).
- [Postimages 공식 플러그인](https://postimages.org/plugins) / [약관](https://postimages.org/terms): 공식 업로드 화면을 통한 통합과 비공식 자동 업로드를 구분한다.
- [Imgur 약관](https://imgur.com/tos).
- [Drive 파일 필드](https://developers.google.com/workspace/drive/api/reference/rest/v3/files) / [R2 공개 버킷](https://developers.cloudflare.com/r2/buckets/public-buckets/).

사이트에 로그인 기능이 있는 것과 타사 앱에 업로드 권한을 주는 계정 연결 기능은 다르다. API 키 방식과 OAuth 방식도 구분한다. 게시판용 플러그인의 존재만으로 Wonboard의 작성 경험과 호환된다고 결론 내리지 않는다.

## 다음 결정에서 반드시 비교할 기준

- [ ] **사용자 소유와 통제:** 자기 계정에 업로드되는가? 파일 조회·일괄 백업·삭제·연결 해제를 사용자가 수행할 수 있는가? 공유 개발자 계정에 사용자 파일을 몰아넣지 않는가?
- [ ] **접근성:** 일반 사용자가 NAS·도메인·클라우드 콘솔 없이 시작할 수 있는가? 회원가입, 결제, 키 발급, 권한 승인 단계를 실제로 기록한다.
- [ ] **경제성:** API·직접 삽입·전송량의 무료/유료 범위, 비용 부담자, 한도 초과·구독 해지 후 동작을 공식 정책과 계정 시험으로 구분해 확인한다.
- [ ] **작성 경험:** 이미 문서에 넣은 사진을 다시 고르지 않고 게시 준비 때만 올릴 수 있는가? 순서·표시 폭·게시용 파일명을 보존하며 일부 실패만 재시도할 수 있는가?
- [ ] **공개 URL:** 로그인 없는 별도 브라우저와 실제 목적지 게시판에서 표시되는가? 만료되는 업로드/미리보기 주소가 아닌가? 토큰 만료·로그아웃·제목 변경·연결 해제가 기존 게시글을 깨뜨리지 않는가?
- [ ] **보존과 이전:** 계정 비활동·파일 삭제·사업자 종료·도메인 변경·구독 해지의 영향을 확인한다. 사진 백업과 기존 게시글 URL 보존은 별개임을 명시한다.
- [ ] **운영 책임:** Wonboard는 업로드 연결만 맡는가, 독자에게 이미지 전달도 맡는가? 회사 서버 없이 기존 게시글이 계속 보이는가? 약관·공개 범위·개인정보·남용 대응 책임은 누구에게 있는가?

## 확정하지 않은 제품 선택

Client를 독립적으로 유지하고 게시판 서버와 이미지 제공 기능을 분리하는 방향은 검토 중이다. Google Drive를 백업 전용으로 축소하거나 ImgBB를 첫 제공자로 채택하는 것은 아직 승인되지 않았다. 자체 고정 도메인 중계도 미확정이다. 5년 보존 요구를 삭제하지 않되, Wonboard 또는 제3자의 무조건적인 보증으로 홍보하지 않는다.

작은 첫 검증을 하더라도 기준은 로그인/계정 연결 → 기존 초안의 합성 사진 업로드 → 직접 이미지 URL → 비로그인 표시 → 로그아웃 후 표시 유지 → 사용자 계정에서 파일 관리다. API 문서가 있다는 것만으로 검증 완료 처리하지 않는다. API 비밀값은 클라이언트 번들·Git에 넣지 않는다.

## 재개와 권한 경계

다음 작업자는 이 이슈, `docs/planning/progress.md`, `docs/planning/web-first-plan.md`와 실제 PR/브랜치 상태를 먼저 확인한다. 지원은 지금 저장소 선택을 결정하지 않았다. 후보 비교와 읽기 조사는 가능하지만, 오늘의 PR 요청을 새 공급자 구현·구독·외부 계정 생성·기존 파일 공개·배포 승인으로 해석하지 않는다. 기존 로컬 초안과 `.env.local`은 보존한다.

결정을 재개할 때 위 비교표를 증거로 채우고 추천안 하나와 감수할 단점을 제시한다. 사용자의 비용·소유권·운영 책임 선택이 필요한 지점에서 멈춘다. 이 이슈는 작성기 PR이 병합되어도 자동으로 닫지 않는다.
