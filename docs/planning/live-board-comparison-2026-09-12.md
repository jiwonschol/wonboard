## 발견

- 정상 표현 훼손 후보: Codex 글에서 `아닌데 → 다닌데`, 서비스명 `클로드 → 클로스` 및 조사 결합형까지 제안했다. 출판 글에서는 `만들어보고자 → 만들 어보고자`, `입문자용 → 입문 자용`으로 어휘 내부를 부당하게 분리했다. 모호함 표시가 있어도 실제 수정 버튼에 잘못된 후보가 제공되는 문제다.
- 수정 후보 없는 탐지: Codex 글의 `좋타고`, 접속 질문의 `몇년`, `제쪽`에는 미등록만 제시한다. `못불러오는`에서는 어절 일부만 잘라 미등록으로 안내한다. 사용자가 필요한 수정안을 얻지 못한다.
- 누락: 금융 글의 `수 밖에`, Codex 글의 `괜찮아 졌습니다`, 출판 글의 `지난 주`, `어마어마 하네요`에 해당 수정 후보가 없다. 이 문맥에서는 각각 붙이는 교정을 검토해야 한다.
- 부분 수정: Codex 글의 기간 표현은 뒤쪽 조사 결합만 수정하고 앞쪽 접미사 결합은 해결하지 못한다.
- 정상 활용형 부담: 금융 글의 `시작했으니까요`, `잘되고` 등에도 미등록 안내가 남았다. 이를 맞춤법 오류로 집계하지 않았다.
- 기존 수정 효과: 금융 글의 삭제·강등 피동 표현은 더 이상 잘못 분리하거나 미등록으로 안내하지 않았다. 월말 띄어쓰기, 국가와 금리 표현, 부정 표현에는 기존 의도한 후보가 나왔다. 회의 글의 서술 연결과 보조 용언 띄어쓰기 후보도 확인했다.

## Chrome 제약 및 재현 자료

게시판 본문 읽기는 성공했다. Chrome 콘텐츠 파일 내보내기는 미지원이었다. 로컬 편집기 탭은 처음 탐색 중 연결 실패 후, 재연결 시 Chrome이 다른 확장 프로그램 UI가 열려 있어 자동화를 차단했다고 명시했다. 따라서 이번의 실제 편집기 클릭·수정 대조는 완료하지 못했다. 이를 MCP 부재나 Chrome 전체 불가로 해석하지 않는다.

원문 및 예측은 Git에서 제외되는 `local-corpora/reports/live-chrome-2026-09-12/`에만 보관했다. 실행: `node local-corpora/reports/live-chrome-2026-09-12/compare.mjs`. `samples.json`은 사전 기대 목록, `predictions.json`은 기본 결과, `personal-predictions.json`은 개인 사전 비교 결과다. 엔진·UI 구현은 이번 진단에서 수정하지 않았다.

다음 구현 우선순위는 정상 활용·접미 파생어의 내부를 끊는 후보 차단, 미등록으로만 나오는 실제 오류의 후보 제공, 어절을 가로지르는 누락 순이다. 새 원문을 개발 사례로 반영하면 독립 보류 자료로 재사용하지 않는다.
