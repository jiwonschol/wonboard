# 개인 ChatGPT Sites 설치판 실행 계획

2026-09-07. 지원이 개인 Sites 시험 배포와 다음 제품 방향을 승인했고, 후속 요청에서 기존 클라이언트를 재사용한 구현까지 지시했다. 개인 Sites용 서버·저장 연결·안내·공개 이미지·HTML 내보내기는 로컬에 구현했다. 이후 별도 Work 작업으로 시험 Site를 배포하고 실제 크롬에서 소유자 연결, 편집기 진입, 문서·사진 저장과 새로고침 복원을 확인했다. 지원의 추가 승인으로 사이트 접근을 공개로 전환했으며, 선택한 게시용 사진 한 장은 로그인 없는 외부 페이지에서 표시되고 초안·원본의 익명 접근은 거절됨을 확인했다. 전체 수명주기와 실제 게시판 호환 검증은 아직 남아 있다. 기존 Onsoon Labs Site, 도메인, 로컬 초안은 변경하지 않았다.

현재 Codex 작업에는 Sites 생성·저장소·배포 호출 도구가 없다. 앞서 지원이 지정한 기존 ChatGPT 대화 [「계획서 구현 가능성 검토」](https://chatgpt.com/c/6a9dfb79-dc28-83e8-a75c-ab26d42aa45f)도 같은 도구 부재로 Site를 만들지 못했다. 이 두 환경에서의 실패와, 아래 별도 Work 작업에서 성공한 실제 배포를 구분한다. 재개할 때에는 아래 기존 시험 Site부터 확인하고 중복 생성하지 않는다.

후속 승인으로 Sites의 사이트 만들기용 **별도 ChatGPT Work 작업**을 시작했다. 작업 ID는 `6a9e143d-6b18-83ee-a349-a7ad9443b813`이다. 공식 Sites 연결 패키지와 Drizzle 도구 추가, 새로운 시험용 D1/R2 연결 및 초기 DB 생성이 승인됐다. 기존 Onsoon Labs Site와 운영 데이터는 계속 범위 밖이다. Work 작업 생성과 실제 Site 생성·배포는 구분하며, 이 작업의 결과를 확인한 뒤 이어 간다.

이 Work 작업이 별도 [Wonboard Media Lifecycle Test](https://wonboard-media-test.b79fff42-6d7b-4203-81c5-342635917d97.chatgpt.site)를 생성했다. 첫 크롬 접속은 소유자 서버 설정이 없어 막혔으며, 후속 승인으로 설치 상태 재확인·계정 연결 안내를 추가했다. 실제 로그인한 크롬에서 읽은 Site별 ID를 서버 secret 환경변수로 연결한 뒤 소스 버전 2·환경 revision 1의 비공개 재배포가 성공했다. 이후 편집기 진입과 합성 문서 한 개의 저장·새로고침 복원을 직접 확인했다. 이번 후속 작업은 **Only you를 유지**했으며 공개 전환은 하지 않았다.

브라우저 자동화의 파일 선택이 `Not allowed`로 거절됐던 부분은 지원이 직접 사진 한 장을 첨부해 이어갔다. 사진의 저장·새로고침 복원과 게시 등록을 확인한 뒤, 지원이 사이트 공개 접근을 승인했다. 현재 접근은 **Anyone on the internet / public**이며 공개 정책 revision 2, 소스 버전 2, 환경 revision 1을 사용한다. 정책만 바뀌었고 재배포·DB 변경은 없었다. 선택한 게시용 사진은 익명 GET/HEAD 200과 이미지 MIME을 반환하며, 별도의 로그인 없는 Chrome 문맥과 다른 출처의 HTML img에서 1200×512 자연 크기로 표시됐다. 문서 본문·목록·원본·게시 상태 API는 익명 요청에 401이었다.

현재 재진입 지점은 **나머지 이미지 수명주기와 반복 설치 검증**이다. 실제 다른 계정 로그인, 재배포 후 이미지 보존, 철회·재공개는 미검증이다. 현재 게시용 사진은 사용자가 첨부한 자료이므로 합성 fixture로 간주해 임의로 삭제·철회·바이트 변경하지 않는다. 기존의 합성 이미지 한 장 시험 승인과 현재 사진의 외부 표시 승인을 구분한다. 공식 Sites 연결·초기 마이그레이션을 적용한 Work checkout의 재사용 diff도 로컬 모노레포에 회수·검토해야 한다. 실제 커뮤니티의 서식 호환과 장기 보존까지 완료로 취급하지 않는다. 상세 결과는 [진행 기록](./progress.md)에 남긴다.

## 목적과 확정된 방향

사용자는 자기 ChatGPT에 원보드를 설치해 달라고 요청하고, 자기 계정의 Sites에서 자신의 글과 사진을 관리한다. Onsoon Labs가 모든 사용자의 이미지를 받아 중계하는 구조를 전제로 하지 않는다.

- 원보드 클라이언트의 기존 글 목록·편집기·사진·ko/en UI를 재사용한다. 목록은 Ulysses처럼 간단하고, 문서를 열면 현재 워드프로세서형 편집기가 나타난다.
- Sites가 제공하는 HTTPS 주소를 기본 사용한다. 개인 도메인·Cloudflare 계정·API 키 수동 입력을 설치 조건으로 요구하지 않는다.
- ChatGPT의 Sites 목록에서 열기와 일반 브라우저에서 개인 사이트 주소로 열기는 같은 앱과 같은 보관함으로 연결한다. 별도 중앙 원보드 웹앱에서 타인의 Sites에 접속하는 연동은 이번 범위에 추가하지 않는다.
- 설치자 본인만 글 목록·초안·원본·업로드·편집·삭제에 접근한다. 단순히 ChatGPT 로그인에 성공한 모든 방문자를 소유자로 취급하지 않는다.
- 사용자가 게시 준비로 선택한 이미지에만 외부 독자가 로그인 없이 접근할 수 있는 주소를 제공한다. 사이트 공개가 초안과 원본의 일괄 공개를 뜻하지 않도록 한다.
- 한 번 발행한 이미지의 주소는 제목 변경·재배포·로그아웃만으로 바뀌지 않아야 한다.
- 코드와 서버 구성은 기존 MIT 모노레포 안에서 유지한다. Sites 계정 자격증명·업로드 파일·배포 식별자는 재사용 배포 템플릿에 넣지 않는다.

## 설치 경험

원클릭은 설치의 시작점을 뜻한다. 실제로 검증한 공식 진입 방식만 사용하고, 확인되지 않은 원클릭 설치 API나 URL 규약을 만들어내지 않는다. OpenAI가 요구하는 로그인·약관·공개 승인 절차를 원보드의 안내 화면이 대신 승인하지 않는다.

1. **원보드 설치 시작:** ChatGPT의 Sites 작업에서 정해진 원보드 버전의 코드를 가져온다. 매번 프롬프트로 UI를 새로 생성하지 않는다. 도메인 설정은 없다.
2. **내 계정 확인:** 플랫폼이 확인한 로그인 정보를 표시하고, 해당 개인 설치의 소유자를 안전하게 확정한다. 설정용 키나 비밀번호를 복사하게 하지 않는다.
3. **짧은 안내:** 초안은 본인만 볼 수 있고, 게시 준비한 사진은 주소를 아는 사람이 볼 수 있으며, 계정·서비스 조건에 따라 제공이 중단될 수 있음을 알린다. 권리가 있는 자료만 올려야 한다는 주의와 자세한 약관·개인정보 안내 링크를 제공한다. 원보드의 고지가 법적 책임 전부를 면제한다고 표현하지 않는다.
4. **확인하고 시작:** 마지막 버튼에 공개 범위의 결과를 설명한다. 동의를 미리 선택하거나 사용자 대신 누르지 않는다. 모든 기존 문서·이미지를 이때 자동 공개하지 않는다.
5. **내 글 목록:** 별도 홍보 페이지 없이 기존 작성 공간을 연다. 사진 삽입·미리보기·보관 상태를 실제 동작에 맞게 표시한다.

안내는 ko/en을 함께 구현한다. 간결한 고지는 완성된 법률 검토나 OpenAI 자체 약관의 대체가 아니다.

## 실행 순서와 완료 기준

### 0. 배포 경로 확인 — 실배포의 현재 재진입 지점

- Sites building/hosting 지침과 해당 환경의 실제 도구를 다시 확인한다.
- Site 생성, 정보 조회, 저장소 연결, 버전 저장, 배포와 상태 조회를 실제로 호출할 수 있어야 한다. 스킬 파일이 설치돼 있거나 계정 화면이 열린 사실만으로 통과시키지 않는다.
- 현재 Git 변경과 PR의 실제 버전을 확인한다. 검사했던 기준은 codex/web-editor-checkpoint의 21529e0b52ff6fe596017a7b77f96ec754c3b75b이며 새 실행 시 갱신한다.
- 기존 저장소의 package manager·편집기·문서 형식을 보존한다. 현재 루트에 새 사이트 생성기를 실행해 프로젝트를 덮어쓰지 않는다.
- 호출 경로가 계속 없으면 외부 배포를 멈춘다. 지원이 별도로 요청한 가역적인 로컬 구현·검증은 진행할 수 있지만 이를 실배포 증거로 대체하지 않는다. 비공개 API 추측, 숨겨진 브라우저 자격증명 추출, Sites 대신 다른 호스팅으로 배포하는 우회는 하지 않는다.

### 1. 합성 이미지 한 장으로 실제 Sites 검증

지원이 승인한 별도 시험용 Site만 사용한다. 기존 Onsoon Labs Site나 onsoonlabs.com을 변경하지 않는다. 실제 사용자 초안·사진 대신 작은 합성 PNG 한 장을 쓴다.

- Sites가 관리하는 파일 저장소에 이미지를 저장하고, 원본 파일과 공개 응답의 바이트 일치를 확인한다.
- 비공개로 설치를 준비하고, 플랫폼이 확인한 소유자와 앱의 소유자를 연결한 뒤에 공개 이미지 경로를 연다. 공개 사이트의 첫 방문자를 소유자로 지정하지 않는다.
- 소유자 전용 업로드·삭제와 익명 공개 이미지 요청을 분리한다. 플랫폼 인증을 흉내 낸 클라이언트 입력은 신뢰하지 않는다.
- 필요한 저장소는 최소로 사용한다. D1을 선택하더라도 기존 운영 DB 변경이나 프로덕션 마이그레이션은 별도 승인 없이 실행하지 않는다.
- 시험용 Site 공개와 합성 파일 업로드는 승인 범위다. 플랫폼이 최종 공개 확인을 요구하면 실제 사이트와 공개 범위를 제시해 그 절차를 따른다.

필수 검증은 다음 여섯 항목이다. 각 항목은 실제 응답·브라우저 결과로 기록한다.

1. 인증 없는 초안·목록·업로드·삭제 접근이 거절된다. 다른 사용자의 인증을 검증하지 못하면 그 항목은 미확인으로 남긴다.
2. 공개 이미지 주소는 인증·쿠키·시간제한 서명 없이 image/png 또는 image/jpeg 응답을 제공한다.
3. 별도 출처의 HTML img 요소에서 자연 크기가 0보다 크고 원래 사진이 표시된다. 단순 HTTP 200만으로 통과시키지 않는다.
4. 소유자 로그아웃과 재배포 후 같은 URL의 파일 해시가 유지된다.
5. 공개 철회 후 관리 가능한 이미지 경로·파생본·Sites/CDN 응답을 통해 계속 공개되지 않는다. 소유자의 비공개 원본 접근은 유지한다. 제3자 캐시·복제본이나 사용자가 이미 내려받은 사본까지 회수한다고 약속하지 않는다.
6. 공개 상태를 복구할 때 기존 주소에 다른 사용자의 파일을 연결하지 않는다.

이 시험은 영구 보존, 대량 이미지 호스팅 허용, 계정 해지 후 서비스 유지의 증명이 아니다. 요금제 변경·탈퇴·한도 소진을 지원 계정으로 시험하지 않는다.

### 2. 기존 클라이언트 연결

로컬에서는 서버 연결 코드를 먼저 구현하고 실제 SQLite 및 메모리 파일 저장 대역으로 검증했다. 실제 계정의 클라이언트 연결·사용자 자료 저장은 첫 시험이 통과한 뒤 진행한다. 공개 배포용 인증이 준비되기 전에 현재 개발 서버나 시험 서버를 인터넷에 노출하지 않는다.

- document/editor/renderer/locales 패키지와 기존 글 목록 UI를 재사용한다.
- 개인 보관함의 문서와 미디어 상태는 서버에서 소유권을 검사한다. 브라우저 자동 저장은 작성 중 복구를 보완하며, 클라우드 저장이 없는 상태를 동기화 완료라고 표시하지 않는다.
- IndexedDB에 남은 기존 localhost 초안은 자동 이사하거나 지우지 않는다. 기존 ZIP 가져오기를 사용자가 선택하는 이사 경로로 유지한다.
- 게시용 이미지 변환과 실제 파일 크기를 검증한다. 현재 드래그 폭 조절이 원본 바이트 압축까지 한다고 가정하지 않는다.
- 공개 이미지 ID와 표시 파일명을 분리한다. 제목을 바꿔도 이미 커뮤니티에 붙인 주소는 유지한다.
- 초안의 미사용 사진 정리 규칙을 공개 저장소 파일 삭제에 그대로 적용하지 않는다. 발행된 이미지의 수명은 별도로 관리한다.
- 공개 URL이 든 HTML을 전용 내보내기로 만든다. 현재 편집기 내부의 Blob URL·미디어 ID를 외부 게시판으로 내보내지 않는다.
- 같은 개인 사이트를 다시 열었을 때 글 목록·이미지·수정 내용이 남는지 확인한다. 기존 한국어 조합 입력·사진 순서·줄바꿈을 보존한다.

### 3. 재현 가능한 설치 패키지

- 검증한 코드를 버전으로 고정하고, 설치 프롬프트와 설정 지침을 저장소에 제공한다. 사이트 소유자·주소·비밀값을 하드코딩하지 않는다.
- Sites에서 새 설치를 시작할 때마다 같은 작성 UI와 기능이 만들어져야 한다. 임의 재생성된 유사 편집기를 원보드 설치로 취급하지 않는다.
- 첫 실행 안내를 기존 UI 안에 넣고, 완료 상태는 서버에서 보존한다. 새로고침마다 설치를 반복하지 않는다.
- 별도 새 설치에서 설치자 인증, 문서 저장, 공개 이미지, 내보내기까지 재현해야 원클릭 설치 완료로 판정한다. 연결 도구나 공식 진입 규약이 없으면 설치 안내 제공까지만 완료로 기록한다.

## 질문 없이 선택할 수 있는 것

- 기존 UI를 유지하는 작은 파일 분리, 내부 함수명, 접근 가능한 버튼 배치.
- 시험에 쓸 합성 이미지의 색상과 작은 해상도. 실제 개인 사진은 사용하지 않는다.
- 기존 테스트 구조에 맞는 회귀 테스트와 한영 안내 표현. 보존기간·구독·제재 정책을 임의로 새로 확정하지 않는다.

## 구현된 코드와 배포 인계 계약

새 의존성이나 lockfile 변경 없이 기존 React/Vite 도구로 구현했다. 로컬 로그인과 IndexedDB 모드는 그대로 유지한다.

| 책임 | 파일 |
| --- | --- |
| Sites 로그인 진입·소유자 확인·첫 안내 | `apps/client/src/SitesGate.tsx` |
| 로컬/서버 저장 연결, 선택한 문서의 사진만 읽기 | `apps/client/src/draftRepository.ts`, `useDrafts.ts` |
| 이미지 변환·명시적 공개·복사·철회 UI | `apps/client/src/publishing.ts`, `PublicationPanel.tsx` |
| 안전한 HTML 직렬화와 공통 렌더링 | `apps/client/src/htmlExport.tsx`, `packages/renderer/src/index.tsx` |
| 소유자 전용 API·공개 이미지 응답 | `apps/server/src/sites/worker.ts`, `http.ts`, `types.ts` |
| 초기 SQL 구조와 Worker 빌드 확인 | `apps/server/src/sites/schema.sql`, `vite.sites-worker.config.ts` |

### 인증과 저장

- 플랫폼의 신뢰할 수 있는 요청 중계가 전달한 `oai-authenticated-user-id`를 사용한다. 이메일·화면 이름은 표시용이며 권한 판단에 사용하지 않는다.
- 설치자가 비공개 Site에서 로그인한 뒤 `/api/sites/identity`로 확인한 Site별 ID를 설치 도구가 서버의 `WONBOARD_OWNER_ID`에 연결해야 한다. 이 값과의 비교 및 설치 DB의 소유자 일치를 모두 검사한다. 미설정 상태에서는 쓰기·읽기를 거절한다. 일반 방문자가 `/setup`을 먼저 눌러 소유권을 얻는 경로는 없다.
- 실제 플랫폼에서 로그인된 크롬의 계정 연결 UI로 이 ID를 확인하고, Work 작업의 공식 환경변수 변경 도구로 서버에 연결한 뒤 편집기 진입까지 검증했다. 다른 계정에서의 반복 설치는 미검증이다. 설치자의 ChatGPT 계정 ID를 Site별 ID와 같다고 가정하지 않는다. 원본 `oai-*` 헤더를 누구나 넣을 수 있는 일반 공개 Worker에 그대로 배포하면 안 된다.
- 런타임 바인딩은 D1 `DB`, R2 `MEDIA`, 프런트엔드 파일 제공 `ASSETS`다. 원본 바이트는 R2, 문서·해시·공개 ID는 D1에 둔다. R2 버킷 자체는 공개하지 않는다.
- 자동 저장은 비공개 원본과 초안을 서버에 저장한다. 업로드 후 문서 저장 실패 시 성공으로 표시하지 않는다. 저장 중 변경과 다른 탭의 오래된 수정은 버전 검사로 보호한다.
- Sites 모드의 새 편집 내용은 오프라인 영속 복구 캐시가 아직 없다. 실패 시 열린 탭의 내용을 보존하고 저장 실패·종료 경고·ZIP 백업 경로를 제공한다. 페이지를 강제 종료한 뒤 복구까지 보장하지 않는다.

### 공개 이미지와 내보내기

- 원본·초안은 비공개다. 사용자가 내보내기에서 미리 선택되지 않은 공개 확인란을 선택하고 실행해야 게시용 사진을 공개한다.
- 브라우저에서 표시 폭의 최대 2배까지 PNG/JPEG를 다시 인코딩하고 원본보다 확대하지 않는다. 비공개 원본은 보존한다. 게시용 바이트와 문서별 불변 공개 ID를 분리한다.
- 주소는 `/media/<public-id>`다. 제목 변경은 파일명에 반영하지만 주소를 바꾸지 않는다. 같은 사진을 다른 글에서 쓰면 글별 공개 여부를 관리한다.
- 익명 GET/HEAD에는 이미지 MIME, `nosniff`, `Cross-Origin-Resource-Policy: cross-origin`, `Cache-Control: no-store`를 제공한다. 철회 시 응답은 404다. 이 선택은 모든 조회마다 공개 상태를 확인하므로 실제 호출 비용·한도 시험이 필요하다.
- 초안에서 사진을 빼도 이전 게시글의 사진을 자동 삭제하지 않는다. 해당 글의 공개 주소 목록을 볼 수 있고 명시적으로 전체 철회할 수 있다. 다시 공개하면 현재 본문 사진에 같은 주소를 사용한다.
- HTML은 공통 렌더러로 생성하며 내부 Blob URL을 거부한다. 서식 복사와 HTML 소스 복사를 제공한다. 수신 게시판이 스타일·iframe을 제거할 수 있어 실제 게시판의 완전 일치까지 보증하지 않는다.

### 로컬 검증과 아직 필요한 배포 작업

`pnpm build:sites`는 `dist/client`와 Fetch API 기반 `dist/server/index.js`를 만든다. **이 결과만으로 Sites 배포용 패키지가 완성된 것은 아니다.** 프로젝트 ID나 `.openai/hosting.json`을 임의로 만들지 않았다.

다음 실행에서는 위 Work 작업의 실제 Sites 도구와 대상 Site 상태를 먼저 확인한다. 공식 `@openai/sites-vite-plugin` 연결과 Drizzle 스키마·생성 마이그레이션 도구 추가, 신규 시험 DB의 초기 테이블 생성은 후속 승인에 포함됐다. 현재 `schema.sql`은 로컬 SQLite 시험 구조이며 운영 마이그레이션으로 적용하지 않았다. 실제 배포 시 스키마를 `db/schema.ts`로 옮겨 생성 SQL을 검사하고, 저장·배포·상태 조회를 공식 절차로 실행한다.

로컬 시험은 `pnpm test:sites`로 실행한다. 해당 설정만 `tests/helpers/sites-vite.ts`를 로드한다. 소유자 헤더와 메모리 R2 대역은 loopback 전용 시험 장치이며 배포 코드에 포함하지 않는다. 기본 Chromium이 설치되지 않은 현재 환경에서는 기존 Chrome으로 `WONBOARD_TEST_CHANNEL=chrome pnpm test:sites --project=chromium`을 실행했다. 전체 수치와 화면 검증은 [진행 기록](./progress.md)에 남긴다.

실제 ChatGPT 로그인, 소유자 문서·사진의 저장·새로고침 복원, 게시용 HTTPS 이미지 주소의 익명 응답과 외부 HTML img 표시를 확인했다. 공개 상태에서 익명 문서·원본 접근도 거절됐다. 다른 실제 계정 차단, 재배포 후 해시 유지, 캐시 철회, 새 계정에 같은 코드 반복 설치는 여전히 실제 Sites 검증 대상이다. 파일 총량·고아 파일 정리·대용량 게시 제한·실제 커뮤니티의 HTML 호환성도 완료로 취급하지 않는다.

## 승인 범위와 금지선

승인 범위는 로컬 구현·검증, 별도 ChatGPT Work 작업 생성과 기존 소스 전달, 공식 Sites 연결 패키지·Drizzle 도구 추가, 별도 시험용 Site와 필요한 최소 D1/R2 저장소 및 초기 DB 생성, 합성 이미지 한 장의 업로드·공개·공개 철회·재배포 검증이다. Sites 자체 소스 저장과 버전 배포는 해당 Site를 제공하는 정상 절차 안에서만 수행한다.

다음은 별도 승인이 필요하다: 새 유료 상품 구매·요금제 변경, 위에 승인된 도구 이외의 외부 라이브러리 추가·제거, 기존 DB 변경·프로덕션 마이그레이션, 원래 파일의 삭제, 실제 사용자 자료 업로드·공개, 기존 Site 변경, GitHub push·PR·merge·main 변경, 대규모 부하, 운영정책의 추가 변경. OpenAI가 별도 확인을 요구하는 권한·약관·공개 절차도 생략하지 않는다.

## 중단 조건과 실패 시 처리

- 실제 Sites 도구가 없거나 등록·연결 권한이 없으면 배포 단계에서 중단하고 필요한 환경 전환을 설명한다.
- 소유자 인증과 익명 이미지 공개를 함께 안전하게 구현할 수 없으면 공개하지 않는다.
- 이미지가 외부 img에서 차단되거나 재배포로 유실되면 원보드 전체 이식 전에 원인을 보고한다. 다른 공급자로 임의 전환하지 않는다.
- 한도·정책·지원 지역·라이선스 조건이 맞지 않거나 새 비용·의존성이 필요하면 근거와 선택을 요청한다.
- 사용자 변경분과 충돌하거나 비밀값의 노출 우려가 있으면 보존하고 중단한다.

## 부록: 이어서 실행할 프롬프트

> 지원은 실시간으로 보고 있지 않다. Wonboard는 사람이 사진이 포함된 글을 편하게 작성하고 자기 커뮤니티에 내보내기 위한 도구다. 지원은 중앙 이미지 호스팅 운영자가 되는 부담을 줄이기 위해 사용자 각자의 ChatGPT Sites에 설치하는 방향을 선택했다. 이 문서와 현재 소스를 먼저 읽고 단계 0의 실배포 확인부터 이어라. 로컬의 Sites 연결·내보내기 코드는 이미 구현돼 있으니 UI나 API를 다시 생성하지 말고 현재 테스트를 재실행하라. 기존 글 목록·편집기·ko/en을 유지하며 별도 도메인과 API 키 수동 입력을 요구하지 마라. 기존 대화 「계획서 구현 가능성 검토」의 시험 Site 상태부터 확인해 중복 생성하지 마라. 별도 시험용 Site에서 합성 이미지 한 장으로 여섯 가지 검증을 수행하고, 통과한 뒤 본체를 실제 연결하라. 로컬 구현·검증과 이 문서에 한정된 시험용 Site 생성·합성 이미지 공개 검증은 승인돼 있다. 공식 Sites 플러그인·Drizzle 도구 추가와 초기 DB 생성 등 추가 승인이 생겼는지 최신 사용자 메시지를 확인하라. GitHub push·PR·merge·main 변경, 새 비용, 기존 DB 변경·프로덕션 마이그레이션, 사용자 실제 자료의 외부 전송·공개는 승인돼 있지 않다. EAS 제출과 다른 서비스 배포도 하지 마라. 확인하지 않은 동작은 미확인으로 남기고, 배포 도구가 없으면 로컬 대역을 실제 Sites처럼 보고하지 말고 배포를 중단하라. 완료 보고에는 실제 배포 주소, 여섯 가지 검증 결과, 재현한 설치 버전과 남은 제약을 포함하라.
