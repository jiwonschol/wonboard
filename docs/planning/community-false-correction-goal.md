# 커뮤니티 교정 제안 오교정 4% 미만 목표

지원이 승인한 목표는 한국어·영어 실제 커뮤니티 글에서 명백한 오교정을 4% 미만으로 낮출 때까지 개선과 새 평가를 반복하는 것이다. 최근 글 재수집을 피하려고 한 달 전·두 달 전·세 달 전 자료를 날짜와 출처별로 나누어 추첨한다. 현재 시작점은 `27c6e3e`의 후보이며, 필요한 수정을 광범위하게 놓치기 전의 비교 기준은 앞 회차에 보존한 `baseline/` 스냅샷이다.

## 이번 목표의 완료 조건

- 분모는 사용자에게 제시하는 **첫 교정 제안 수**다. 분자는 정상 표현을 망가뜨리거나 기존 오류에 새로운 잘못된 단어·경계를 만드는 명백한 오교정 수다. 같은 글의 서로 다른 제안은 각각 센다. 제안 없는 글과 미등록 알림은 분모를 늘리지 않는다.
- 같은 고정 후보가 **서로 겹치지 않는 두 새 평가 묶음에서 각각 4% 미만**이어야 한다. 두 묶음 합계 첫 제안 200개 이상, 한국어·영어 각각 50개 이상을 확보하고, 언어별 합계도 각각 4% 미만이어야 한다. 정수 경계는 엄격히 적용한다. 100개 중 4개는 탈락이다.
- 판정 보류를 오교정이 아닌 것으로 숨기지 않는다. 명백한 오교정과 보류를 합친 보수적 비율도 같은 4% 경계 아래여야 최종 판정한다. 이 수치는 해당 수집 프레임에서의 관측 결과이며 전체 인터넷 모집단의 정확도 보장이 아니다.
- 필요한 교정을 억제해 통과하지 않는다. 새 자료의 예측 전 주석 필수 수정 구간 도달 수가 언어별로 이전의 보수적 억제 전 기준보다 낮아지면 완료하지 않는다. 사라진 유효 제안과 새로 잡은 구간을 따로 기록한다. 최소 한국어·영어 각 30개 필수 수정 구간이 있어야 이 보조 조건을 판정한다.
- 두 언어 모두 최소 두 개 출처, 과거 두 개 이상 월의 글을 포함한다. 2026년 6·7·8월을 초기 목표로 삼고 월별 층을 고르게 구성한다. 출처·월별 결과와 표본 수를 따로 보고한다. 특정 사이트나 편한 정상 글로 분모를 채우지 않는다.

초기 수집 프레임 소진 뒤에는 본문을 보기 전에 확장 범위를 고정한다. 접근 가능한 미노출 목록을 확보하기 위한 추가 범위는 한국어·영어 모두 2025년 1월~2026년 8월이다. 출처별 접근 가능한 목록 안에서 추첨하며, 프레임이 없는 월을 확보한 것으로 보고하지 않는다. 각 확장 정책과 프레임·선택 해시는 로컬 평가 자료에 보존한다. MoneySavingExpert의 기존 목록을 모두 사용하면 같은 공개 생활 게시판에서 2025년 1~9월 목록을 새 범위로 고정해 확보한다. 이 확장은 본문을 보기 전에 정하며 과거 기간과 새 요청 수를 해당 회차 계획에 기록한다. 기존 생활 게시판의 미노출 목록도 소진되면 같은 포럼의 Energy, Water bills, Phones & TV, Broadband & internet access, TV MoneySaving, Techie Stuff 공개 게시판으로 확장한다. 이때도 2025년 1월~2026년 8월 범위와 목록 페이지 상한을 본문 수집 전에 고정한다.

MoneySavingExpert의 위 6개 게시판에서 2025년 이후 미요청 토론이 소진되면 같은 게시판의 기간을 2024년 1월~2026년 8월로 확장한다. 토론 식별자는 URL 표기나 ID 접두사 대신 `/discussion/<숫자 ID>`로 정규화해 모든 과거 선택·요청·확보 기록과 대조한다. 기존 메타데이터를 재사용하고 필요한 추가 목록은 게시판별 최대 40페이지로 본문 수집 전에 고정한다. 결과를 보고 글을 보충하지 않는다.

HN의 기존 월별 미노출 목록이 소진되면 같은 Ask HN 공개 API에서 2024년 9월~2025년 8월 메타데이터 프레임을 고정한다. 본문 수집 전에 월별 추첨을 완료하며, 미노출 글이 없는 월의 부족분을 다른 월에서 결과에 따라 채우지 않는다.

위 조건은 이번 반복 실험의 완료 기준이다. 기존 제품 문서의 전체 배포·UI·개인 사전·언어 품질 완료를 대신하지 않는다.

## 수집·개선·평가 순서

1. 과거 공개 목록이나 정식 공개 API에서 게시일을 확인한다. 월·출처별 후보 URL 목록을 먼저 저장하고 프레임 해시·추첨 시드를 고정한다. 목록이 일부만 확보되면 그 범위와 누락을 명시한다.
2. 고정된 후보를 `SHA256(seed + newline + URL)` 순서로 추첨한다. 선택 기준에 본문이나 검사기 결과를 쓰지 않는다. 접근 실패·중복·추출 실패도 선택 순위와 함께 기록한다. 대체 표본은 같은 프레임의 다음 순위로만 얻는다.
3. 이전에 본 모든 URL 및 공백·HTML entity를 정규화한 본문 중복을 제외한다. 발췌는 글당 첫 25개 공백 구분 단어로 시작한다. 공지·홍보·약관은 별도 층이며, 짧은 질문·웃음·사용자 부품 목록은 실전 입력으로 포함한다.
4. 기존 실패 자료로 코드를 개선하고 관련 회귀를 검증한다. 새 평가 본문·라벨·예측을 구현자가 보기 전에 검사기·사전 스냅샷을 고정한다. 수집 담당자는 제품 코드와 예측을 보지 않는다.
5. Luna가 원문을 주석하고 부모가 형식·누락·허용형을 검토한다. 초벌은 소묶음으로 저장해 잘못된 원문 구간 때문에 전체 결과가 사라지지 않게 한다. 모델 합의를 전문가 정답으로 취급하지 않는다.
6. 동일 입력을 기준 검사기와 후보에 한 번씩 실행한다. 최초 입력·라벨·예측은 덮어쓰지 않는다. 모든 첫 제안을 검토하고, 오교정과 유효 교정 손실을 모두 센다. 사후 라벨·출처 정정은 별도 산출물로 남긴다.
7. 실패하면 그 묶음은 개발 자료로 전환한다. 개선 후에는 다음 미노출 묶음으로 다시 평가한다. 성공한 첫 묶음을 본 뒤 코드를 바꾸면 연속 통과 횟수는 초기화한다.

## 자원·중단·재진입

로컬 모델을 실행하거나 다운로드하지 않는다. 공개 자료 요청·파싱과 단발 JavaScript 검사만 로컬에서 수행한다. 유료 API, 새 의존성, 원격 push·PR·merge·배포는 이번 실행 범위에 없다. 차단·robots·접근 챌린지를 우회하지 않는다. 사이트 하나가 막히면 다른 허용 출처를 조사한다. 모든 필요한 출처에서 같은 외부 장애가 반복되어 더 진행할 수 없다면 확보한 자료·접근 로그·부족한 완료 조건을 남긴다.

작업 산출물은 `local-corpora/historical-goal-2026-09-27/`에 보존한다. 언어별 수집은 `collection/ko/`, `collection/en/`, 개발 비교와 후보 스냅샷은 회차별 디렉터리에 둔다. 최초 기준 및 이전 실패 자료는 `local-corpora/live-round2-2026-09-27/`를 그대로 사용한다. 사용자 소유 `docs/.DS_Store`는 그대로 둔다.

재진입 실행 지시: 지원은 실시간으로 보고 있지 않다. 저장된 활성 goal, 이 문서, 현재 브랜치 및 변경 파일, 가장 최근 회차 보고서를 확인하라. 과거 목록 프레임을 먼저 고정하고 새 표본에서 코드 수정 효과를 검증하라. 명백한 오교정 4% 미만 및 위 최소 표본·언어·누락 방지 조건을 충족할 때까지 가역적인 구현·수집·검증을 계속하라. 자체 재평가나 같은 모델 판정만으로 성공을 선언하지 말고, 성공·실패한 최초 결과를 모두 보존하라. 이미 노출된 자료를 새 평가에 섞지 마라.
