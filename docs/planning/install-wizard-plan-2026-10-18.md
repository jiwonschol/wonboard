## 왜 하는가

지원이 새 계정으로 설치를 해 보다가 1단계에서 막혔다. 소개 페이지의 설치 버튼은 chatgpt.com을 여는데, 그 화면은 기본이 **Chat**이고 Chat에는 Sites가 없다. ChatGPT는 설치 문장 1단계의 「가져올 수 없으면 ZIP을 첨부하라고 안내」를 따랐고, 사용자는 할 수 없는 일을 요구받았다.

지원의 결정(2026-10-18): **베타라도 새 사용자가 한 번에 막힘 없이 끝까지 가야 한다. 「설치 문장을 붙여넣고 나머지는 ChatGPT에게 맡긴다」가 아니라, 원보드가 단계마다 할 일과 확인할 화면을 보여 주는 설치 마법사를 둔다.**

같은 날 지원의 다른 Plus 계정으로 **Work** 화면에서 설치 문장을 그대로 보내자 설치가 끝까지 됐다. 그래서 이 계획의 사실 근거는 그 실제 실행이다. 공식 문서만으로 쓴 지난 안내와 다른 점이 여럿 드러났다.

## 2. 지켜야 할 기존 규칙

새 아이디어보다 아래 회귀를 먼저 막는다.

1. **태그는 `package.json`의 `version` 한 곳에서 정한다.** 설치 문장의 저장소 줄과 ZIP 주소는 `v${version}`이고, 설치 안내·소개 페이지에는 태그를 직접 적지 않는다. `scripts/build-site.mjs:84-104`가 검사한다. 마법사 페이지도 같은 검사 대상에 넣는다.
2. **설치 문장은 사용자가 원문 그대로 복사하는 글이다.** 자리 표시자를 둘 수 없다.
3. **“…”(둥근 따옴표)로 적은 문구는 원보드 화면에 실제로 나오는 문구여야 한다.** `scripts/build-site.mjs:73-76`이 `packages/locales`에서 찾는다. ChatGPT·Sites 화면의 문구는 「…」로 적는다(예: 「ChatGPT로 Work 시작」, 「ChatGPT로 계속」). 마법사 페이지도 이 검사에 넣는다.
4. **main 브랜치 ZIP 주소를 쓰지 않는다**(`build-site.mjs:94`).
5. **사이트 접근 범위를 넓히라고 안내하지 않는다.** 소유자가 정해지기 전에 범위를 넓히면 먼저 로그인한 아무나 소유자가 된다(설치 문장 4단계).
6. **확인한 것과 확인하지 않은 것을 나눠 적는다.** 설치 안내 「확인된 것과 확인되지 않은 것」 표를 유지·갱신한다.
7. **소개 페이지 빌드는 의존성 없이 돈다.** pages 워크플로는 `pnpm install` 없이 `node scripts/build-site.mjs`만 돌린다(`.github/workflows/pages.yml:39`). 마법사에 npm 패키지를 쓰지 않는다.
8. **`.github/workflows`는 이 작업에서 고칠 수 없다**(PR #54 기록). `pages.yml`의 감시 경로에 `site/**`가 이미 있어 새 파일도 배포된다.
9. ChatGPT와 Sites는 OpenAI의 서비스이고 원보드는 별개라는 문구를 마법사 페이지에도 둔다(`site/index.html` 바닥글과 같게).

## 3. 관찰 요약과 현재 구조

### 시험 설치에서 본 것 (2026-10-18, 웹, Plus 계정, 모델은 Work 기본값)

- chatgpt.com 위쪽 가운데에 「Chat | Work」 전환이 있고 기본은 Chat이다(캡처 02). 계정 이름 아래에 요금제(「Plus」)가 보인다.
- Work를 누르면 입력창 문구가 「ChatGPT로 Work 시작」으로 바뀐다(캡처 03). 주소는 Chat과 Work 모두 `chatgpt.com/`라서, 링크로 Work를 바로 여는 방법은 찾지 못했다.
- Work에서는 GitHub 태그를 바로 가져왔다. ZIP은 필요 없었다(캡처 05·06, 커밋이 태그와 일치).
- 시스템 pnpm 11.25.0으로 시작했다가 멈추고 11.19.0으로 다시 설치했다(캡처 07). 설치 문장의 버전 고정이 지켜졌다.
- **승인 요청은 한 번도 없었다.** 보낸 뒤 4분 2초 만에 배포가 끝났다(캡처 08~11).
- 배포가 끝나자 ChatGPT 오른쪽에 **사이트 미리보기 창이 저절로 열렸고, 이미 원보드의 “시작 전에 확인해주세요.” 화면**이었다(캡처 10). 원보드는 로그인된 계정이 처음 사이트를 읽을 때 소유자를 기록한다(`apps/client/src/SitesGate.tsx:42-47`, `apps/server/src/sites/worker.ts:145-154`). 그래서 미리보기 창이 사이트를 만든 계정으로 열리는 순간 소유자가 정해졌다. “이 사이트에는 아직 소유자가 없어요.” 화면과 원보드의 “ChatGPT로 로그인” 버튼은 한 번도 보이지 않았다.
- ChatGPT의 완료 요약은 설치 문장대로 사이트 주소, 접근 범위(기본 비공개), Sites 버전, 원본 태그를 표로 줬다(캡처 11). 다만 「“ChatGPT로 로그인”을 눌러 주세요」라고 안내했는데, 이 버튼은 이번 흐름에 나오지 않는다(설치 문장 5단계가 그렇게 시킨다, `docs/install/install-prompt.txt:28`).
- 사이트 주소를 새 탭에서 열면 원보드보다 먼저 **Sites의 로그인 관문**이 나온다: 「접속하려면 로그인하세요」, 「ChatGPT로 계속」(캡처 12).
- 이어서 「ChatGPT로 원보드에 로그인하세요」 **계정 선택 화면**에 이 브라우저의 ChatGPT 계정이 모두 나온다(캡처 13). 다시 열었을 때는 **계정 순서가 바뀌어** 있었다.
- 계정 선택 화면을 오래(약 50분) 열어 두고 고르면 「세션이 종료되었습니다」(`invalid_state`)가 나온다. 사이트 주소를 다시 열면 된다(캡처 14).
- 계정을 고르자 동의 화면 없이 원보드의 “시작 전에 확인해주세요.”로 갔다(캡처 15). 미리보기 창에서 이미 동의된 것으로 보인다. 동의 화면이 나오는 경우는 보지 못했다.
- 확인란에 표시하고 “내 글쓰기 공간 열기”를 누르면 편집기와 「내 글」이 열리고, 빈 「제목 없음」 글 하나가 생긴다. 오른쪽 아래에 Sites가 넣은 「사이트 편집」 버튼이 떠서 편집기 일부를 가린다(캡처 16·17).

### 지금 소개 페이지와 설치 버튼

- `site/index.html:78-83` 설치 순서 4단계. 2번 「유료 요금제 계정으로 로그인한 ChatGPT의 입력창에 붙여넣고 보냅니다」에 Work가 없다.
- `site/index.html:85` 「원보드 설치」 링크가 `https://chatgpt.com/`을 새 탭으로 연다. `site/install.js:29-42`가 누를 때 설치 문장을 복사한다.
- `site/index.html:96` 「다른 계정에서 확인되지 않음」 안내.
- `scripts/build-site.mjs:78-81` 설치 문장 자리 `<!--INSTALL_PROMPT-->`는 `index.html`에 정확히 하나여야 하고, `:119-124`가 `style.css`·`install.js`만 `site/dist`로 복사한다. 새 파일을 넣으려면 이 목록을 늘려야 한다.
- 소개 페이지에는 자동 시험이 없다. 빌드 검사가 유일한 가드다.

## 5. 마법사 설계

### 놓는 곳

`site/install.html`(새 페이지)와 `site/install-wizard.js`. 소개 페이지 `index.html`은 원보드 소개로 남기고, 「원보드 설치」 버튼이 `install.html`로 간다. 설치 문장 자리 `<!--INSTALL_PROMPT-->`는 `install.html`로 옮긴다. `index.html`의 「설치 문장 보기」는 없애거나 `install.html`로 연결한다(구현자가 고른다). `build-site.mjs`의 자리 검사와 복사 목록을 그에 맞춘다.

마법사는 ChatGPT 화면을 볼 수 없다(다른 사이트). 그래서 단계마다 **할 일 하나, 그 일을 하는 버튼, 「이 화면이 보이나요?」 확인 질문 하나**를 둔다. 「예」면 다음 단계, 「아니요」면 그 단계의 갈래 목록이 펼쳐진다.

### 화면 자료

캡처를 잘라 쓴다. 쓸 장면: 02·03(전환 버튼과 입력창 문구), 05 또는 06(코드 가져오기 메시지), 10(미리보기 창), 11(요약 표), 12(Sites 관문), 13(계정 선택), 15(시작 전 확인), 17(편집기). 처리 규칙:

- 왼쪽 사이드바의 대화 제목, 계정 이름, 이메일, 사이트 주소의 하위 도메인은 잘라 내거나 단색 상자로 덮는다. 덮은 자리에 가짜 값(「내 이름」, 「name@example.com」, 「내사이트」)을 쓰는 것은 괜찮다.
- 파일은 `site/install/` 아래, 한 장 150KB 이하, 합계 1.5MB 이하. JPEG나 WebP.
- 각 이미지에 대체 텍스트(그 화면에서 확인할 문구)를 단다. 이미지가 안 보여도 글만으로 따라올 수 있어야 한다.
- 페이지 위쪽에 「화면은 2026-10-18 ChatGPT 웹 기준입니다. 바뀌었을 수 있습니다」를 적는다.
- 이미지 처리 도구는 의존성을 저장소에 넣지 않는 방법으로 고른다(로컬의 Playwright로 캔버스에 그려 저장, macOS `sips`로 자르기 등). 처리 스크립트는 커밋하지 않는다.

### 그 밖의 동작

- 지금 단계를 `localStorage`에 기억해, 사용자가 ChatGPT 탭에 갔다 돌아와도 같은 단계가 열린다. 읽기·쓰기는 try/catch로 감싸고, 없으면 0단계부터. 「처음부터 다시」 버튼을 둔다.
- 단계가 바뀌면 그 단계 제목으로 포커스를 옮긴다. 키보드만으로 끝까지 갈 수 있어야 한다.
- 화면 폭 375px에서 가로 스크롤이 생기지 않아야 한다. 스타일은 `site/style.css`를 그대로 쓰고 필요한 것만 더한다(소개 페이지는 밝은 테마 하나뿐이다).
- 마법사 아래에 「단계별 설치 안내(자세한 설명)」 링크를 둔다. 마법사와 안내의 순서·문구가 같아야 한다.
- 한국어만. 소개 페이지가 한국어뿐이다.

### 빌드 검사에 더할 것

## 6. 작업 순서

한 세션, 한 PR, 커밋 두 개.

1. **사실 교정** (P1~P3, G1~G10, S2·S3): 문서와 설치 문장만 바꾼다. 마법사가 이 문구를 그대로 가져다 쓰므로 먼저 한다.
2. **마법사** (§5, S1): 새 페이지·이미지·빌드 검사.

한 PR로 묶는 이유: 교정된 안내와 마법사가 같은 순서·문구를 써야 해서 따로 머지하면 그 사이에 둘이 어긋난다. 두 커밋으로 나눠 리뷰에서 구분되게 한다.

## 8. 가정과 확인하지 못하는 것

- 화면은 2026-10-18 웹 기준이다. ChatGPT 화면은 예고 없이 바뀐다. 지원은 OpenAI가 Chat과 Work를 합칠 수 있다고 본다. 그래서 단계 문구는 `install.html` 한 파일에 모아 화면이 바뀌면 그 파일만 고치게 한다.
- 시험은 지원의 계정 하나로 한 번 했다. 다른 사람의 계정, 데스크톱 앱, 회사·학교 워크스페이스는 확인하지 않았다(부록 B).
- 구현 세션은 새 시험 설치를 하지 않는다. ChatGPT에서 마법사대로 되는지는 머지 뒤 지원이 확인한다(부록 B).
- 미리보기 창이 사이트를 만든 계정으로 열리는 것이 항상 그런지는 한 번만 봤다. 마법사 4단계의 ①번 갈래가 그 경우를 받는다.

## 왜, 누구를 위해
원보드는 ChatGPT 유료 사용자가 자기 ChatGPT Sites에 설치해 쓰는 글쓰기 도구다. 지금 설치는 「소개 페이지에서 설치 문장을 복사해 ChatGPT에 붙여넣기」뿐이라, 새 사용자가 ChatGPT의 기본 화면(Chat)에 붙여넣으면 Sites가 없어 1단계에서 막힌다. 지원의 결정: 베타라도 새 사용자가 한 번에 끝까지 가야 한다. 원보드가 단계마다 할 일과 확인할 화면을 보여 주는 설치 마법사를 만들고, 실제와 다른 설치 안내·설치 문장을 고친다. 2026-10-18에 지원의 계정으로 Work 화면에서 실제 설치한 기록이 사실 근거다.
