# 문서 v1과 로컬 저장 계약

`packages/document/src/index.ts`가 실행 가능한 검증 정본이다. 제목, 본문 노드, 문서 언어, revision, 미디어 메타데이터를 JSON으로 보관한다. 지원하는 노드는 문단·제목·인용·목록·코드·구분선·줄바꿈·이미지·영상 링크다. 표시 스타일은 허용한 속성만 받는다. 사용자 HTML을 그대로 실행하지 않는다.

`video`는 YouTube/Vimeo provider, 검증한 videoId, Vimeo 비공개 링크의 privacyHash, startSeconds, autoplay를 보관한다. 입력 URL의 autoplay 값은 가져오지 않으며 기본값 false다. 플레이어 주소는 허용한 제공자의 URL만 생성하고 미리보기에서만 불러온다. 임의 iframe HTML은 받지 않는다. 영상 노드를 모르는 이전 구현은 기존의 알 수 없는 노드 보호 규칙에 따라 읽기 전용으로 처리한다.

선택 필드 `autoRenameAttachments`는 생략 시 true다. 게시용 파일명은 최신 제목과 안정적인 가져오기 순서에서 계산한다(`제주 여행_001.png`). 원본 이름과 미디어 ID를 변경하지 않는다. false이면 원본 이름을 그대로 사용한다. 제목의 경로 구분자·제어문자 등은 게시용 이름에서만 제거한다. 실제 공개 업로드는 아직 없으며, 향후 이미 게시된 URL을 제목 변경 때문에 바꾸지 않는다. 공개 주소 식별자와 표시 파일명을 분리한다.

이미지 노드는 mediaId와 표시 폭·정렬·alt·caption을 가진다. 원본 파일명은 메타데이터에 그대로 남고, 내부 ID는 UUID다. PNG/JPEG만 허용하며 이 단계에서는 형식 변환·압축·클라우드 업로드를 하지 않는다. object URL은 실행 중 표시용이며 파일에 기록하지 않는다.

IndexedDB `wonboard-writer-v1`의 `drafts` 저장소에서 문서와 원본 이진 데이터를 한 트랜잭션으로 저장한다. WebKit 테스트에서 Blob 쓰기가 실패하여 영속 저장은 ArrayBuffer를 사용하고 읽을 때 Blob을 복원한다. 이미 저장된 Blob 형식도 읽을 수 있다. 이진 데이터 준비는 트랜잭션을 열기 전에 끝낸다. revision이 예상값과 다르면 기존 문서를 덮어쓰지 않는다.

입력 변경은 350ms 후 자동 저장한다. 한글 조합 중에는 저장을 미루고 조합 종료 후 예약한다. 저장 실패 시 화면의 문서를 유지하고 ZIP 백업을 제공한다. 브라우저 데이터 삭제·저장 공간 회수까지 방어하는 영구 저장소는 아니다. 여러 탭의 동시 수정은 병합하지 않고 충돌을 알린다.

ZIP은 `document.json`과 `media/{id}` 원본을 묶는다. 파일 경로·허용 항목·합계 크기·SHA-256을 검증하고 복원할 때 이미지도 디코딩하여 메타데이터를 확인한다. 복원은 새 documentId를 부여하며 기존 문서를 덮어쓰지 않는다. 알 수 없는 문서 버전·노드는 자동 변환하거나 삭제하지 않고 읽기 전용으로 남긴다.

제한: 파일당 20MiB, 이미지당 4천만 화소, 문서당 이미지 100개, ZIP 합계 256MiB. 화면 글자 수는 Intl.Segmenter 기준이며 입력 안전 상한은 별도다. 검색은 NFC 비교만 수행하고 원문과 macOS 파일명을 정규화해서 덮어쓰지 않는다.

`@wonboard/editor`는 저장·로그인을 소유하지 않는다. 호스트가 제목/본문 변경, 이미지 가져오기, 미디어 URL, 언어를 연결한다. `@wonboard/renderer`는 같은 문서의 제한된 노드를 표시한다. 공개 HTML 내보내기와 목적지별 호환성은 후속 단계다.
