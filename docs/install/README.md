# 원보드 설치 안내 (베타)

원보드는 내 ChatGPT 사이트(Sites)에 직접 설치해서 쓰는 글쓰기 도구입니다. 설치는 [설치 문장](./install-prompt.txt)을 내 ChatGPT에 붙여넣는 것으로 시작하고, 그 뒤의 작업은 내 ChatGPT가 합니다. 이 문서는 각 단계에서 무엇을 보게 되는지, 막히면 무엇을 하면 되는지, 그만 쓰려면 어떻게 하는지를 설명합니다.

빠르게 시작하려면 [원보드 소개 페이지](https://jiwonschol.github.io/wonboard/)의 설치 버튼을 누르세요. 설치 문장이 복사되고 ChatGPT가 열립니다.

설치 문장은 원보드의 정해진 버전(태그)의 코드를 가져옵니다. 어느 버전인지는 소개 페이지의 설치 방법과 설치 문장의 「저장소」 줄에 적혀 있습니다. 같은 설치 문장으로 설치한 사람은 설치한 날과 관계없이 같은 원보드를 받습니다. 이미 설치한 사이트를 새 버전으로 바꾸려면 [새 버전으로 올리기](#새-버전으로-올리기)를 보세요.

## 먼저 알아둘 것

**다른 계정에서 확인되지 않음.** 지금까지 실제 설치는 만든 사람의 계정에서 한 번 한 것이 전부입니다. 그때는 저장소 주소를 알려 주는 대신 코드 ZIP 파일을 ChatGPT 작업에 첨부했습니다. 다른 계정에서 이 안내대로 끝까지 설치되는지는 베타 참가자의 첫 설치로 확인할 예정입니다. 중간에 막히면 [문제 알리기](#문제-알리기)로 알려 주세요. 그 내용으로 이 안내를 고칩니다.

원보드는 무료이고 앞으로도 유료로 바꾸지 않습니다. 원보드에는 회원 가입이 없고, 로그인은 ChatGPT 로그인 하나입니다. ChatGPT 요금은 OpenAI에 내는 것이며 원보드와 관계가 없습니다.

## 필요한 것

| 항목 | 내용 |
| --- | --- |
| 요금제 | ChatGPT Plus·Pro·Business·Enterprise·Edu 중 하나. Sites는 이 요금제에서만 쓸 수 있습니다. |
| 지역 | Sites를 쓸 수 있는 지역이어야 합니다. 유럽경제지역(EEA)·스위스·영국에서는 출시 시점에 Sites 사용이나 공개 게시에 제한이 있었습니다. 제한되는 범위(Sites 자체인지 공개 게시만인지)는 요금제에 따라 다를 수 있고, 2026-10-06에는 OpenAI 도움말 페이지가 열리지 않아 정확한 범위를 확인하지 못했습니다. 이 지역에 있다면 내 ChatGPT에 Sites 메뉴가 보이는지로 먼저 확인하세요. 원보드는 공개하지 않은 사이트로 설치되지만, 게시판에 붙일 사진을 남에게 보이려면 공개 게시가 필요합니다. |
| 기기 | ChatGPT 웹(chatgpt.com) 또는 ChatGPT 데스크톱 앱 |

Sites는 공개 베타입니다. 요금제, 지역, 사용 한도는 OpenAI가 바꿀 수 있습니다. 지금 조건은 [Sites 공식 문서](https://learn.chatgpt.com/docs/sites?surface=app)에서 확인하세요.

무료 요금제(Free·Go)에서는 베타 동안 원보드를 쓸 방법이 없습니다. 데스크톱판은 구독자가 보조로 쓰는 용도이고, 베타 동안에는 설치 파일을 배포하지 않습니다.

회사나 학교의 워크스페이스 계정이라면 관리자가 Sites를 꺼 두었을 수 있습니다. 그런 경우에는 관리자에게 문의하거나 개인 계정을 쓰세요.

## 설치 순서

설치는 일곱 단계입니다. 1·2·4·5·7단계는 내가 하고, 3·6단계는 ChatGPT가 합니다.

### 1. 설치 문장 복사하기

[소개 페이지](https://jiwonschol.github.io/wonboard/)에서 설치 버튼을 누르면 설치 문장이 클립보드에 복사되고 ChatGPT가 새 탭으로 열립니다. 버튼을 쓰지 않으려면 [install-prompt.txt](./install-prompt.txt)를 열어 내용 전체를 복사하세요.

막혔을 때: 복사가 되지 않으면 소개 페이지의 「설치 문장 보기」를 펼쳐 글 전체를 직접 선택해 복사하세요.

### 2. 내 ChatGPT에 붙여넣기

ChatGPT에 유료 요금제 계정으로 로그인했는지 확인한 뒤, 새 대화의 입력창에 설치 문장을 붙여넣고 보냅니다. 문장을 고치지 않아도 됩니다.

보게 될 화면: ChatGPT가 Sites 작업을 시작하고, 진행 상황을 단계별로 알려 줍니다.

막혔을 때:

- ChatGPT가 일반 대화로만 답하고 Sites 작업을 시작하지 않으면, 입력창에서 `@Sites`를 직접 골라 넣은 뒤 문장을 다시 보내세요. 공식 문서는 `@Sites`를 언급하거나 프롬프트에 website라는 말을 넣으면 Sites 작업이 시작된다고 안내합니다.
- Sites 메뉴 자체가 보이지 않으면 요금제와 지역을 확인하세요. 웹에서는 **More > Sites** 또는 chatgpt.com/sites 에서 Sites를 볼 수 있습니다.

### 3. ChatGPT가 코드를 가져와 배포하기

ChatGPT가 원보드 저장소에서 설치 문장에 적힌 버전(태그)의 코드를 가져와 포함된 설정 그대로 빌드하고, 글을 담을 데이터베이스와 사진을 담을 파일 저장소를 만들고, 내 사이트로 배포합니다. 설치 문장은 사이트 접근 범위를 새 사이트의 처음 상태 그대로 두라고 시킵니다. 처음 상태에서는 소유자만 사이트를 열 수 있고, 회사나 학교 워크스페이스에서는 워크스페이스 관리자도 열 수 있습니다. 이 범위는 Sites가 정하는 것이고, 원보드의 소유자 확인과는 별개입니다. 사이트를 열 수 있는 사람이라도 연결된 소유자 계정이 아니면 원보드는 글과 사진을 내주지 않습니다.

보게 될 화면: 작업 도중 ChatGPT가 저장소 만들기나 배포를 승인해 달라고 물을 수 있습니다. 내용을 읽고 승인하세요. 끝나면 ChatGPT가 `chatgpt.site`로 끝나는 사이트 주소를 알려 줍니다. 얼마나 걸리는지는 다른 계정에서 재 본 적이 없습니다.

막혔을 때:

- ChatGPT가 저장소를 직접 가져오지 못한다고 하면, ChatGPT가 알려 주는 코드 ZIP 파일을 내려받아 같은 대화에 첨부하세요. 주소는 [설치 문장](./install-prompt.txt)의 1단계에 적혀 있고, 설치 문장과 같은 버전을 가리킵니다. 다른 버전이나 main 브랜치의 ZIP을 첨부하지 마세요.
- ChatGPT가 원보드와 다르게 생긴 새 사이트를 만들어 버렸다면 그 사이트는 원보드가 아닙니다. 「새로 만들지 말고 저장소의 코드를 그대로 배포해 주세요」라고 다시 요청하세요.
- 빌드나 배포가 실패하면 ChatGPT가 알려 준 오류 내용을 그대로 복사해 [문제 알리기](#문제-알리기)로 보내 주세요. 저장소에는 연결 설정과 새 설치용 DB 마이그레이션이 포함돼 있습니다. ChatGPT가 설정이나 코드를 새로 만들지 않도록 하고, 실패한 명령과 오류를 함께 알려 주세요.
- 요금제 한도에 닿았다는 안내가 나오면 원보드가 풀 수 없는 제한입니다. ChatGPT가 보여 주는 한도 안내를 따르세요.

### 4. 사이트를 열고 로그인하기

ChatGPT가 알려 준 주소를 브라우저에서 엽니다.

보게 될 화면: “원보드 설치가 아직 끝나지 않았어요.”라는 안내와 “설치 상태 다시 확인”, “ChatGPT로 로그인” 버튼이 보입니다. 아직 내 계정이 소유자로 연결되지 않아서 나오는 정상 화면입니다. 같은 화면의 “단계별 설치 안내”를 누르면 이 문서가 열립니다. “ChatGPT로 로그인”을 누르면 ChatGPT 로그인 화면으로 넘어갑니다. 처음 로그인할 때는 이 사이트에 내 기본 프로필을 공유할지 묻는 동의 화면이 나올 수 있습니다. 만든 사람의 계정에서는 이름·사용자명·이메일·프로필 사진이 표시됐고 대화 기록은 포함되지 않았습니다.

막혔을 때:

- 사이트가 열리지 않고 ChatGPT 로그인이나 접근 권한 화면만 나오면, 사이트를 만든 계정과 같은 계정으로 브라우저에 로그인했는지 확인하세요.
- “Site에 연결하지 못했어요.”로 시작하는 안내가 나오면 잠시 뒤 다시 시도하세요. 계속되면 배포가 끝나지 않았을 수 있으니 ChatGPT에 배포 상태를 물어보세요.

### 5. 연결 ID를 ChatGPT에 전달하기

로그인하고 돌아오면 같은 화면에 “계정 연결 정보”가 생깁니다. 이것을 펼치고 “연결 정보 확인”을 누르면 영문과 숫자로 된 연결 ID가 나옵니다. 이 값을 복사해, 설치를 진행하던 ChatGPT 대화에 붙여넣습니다. ChatGPT는 이 값을 사이트의 환경 값 `WONBOARD_OWNER_ID`로 저장합니다.

이 단계가 있는 이유: 원보드는 로그인에 성공한 아무나 소유자로 받아들이지 않습니다. 설치한 사람이 자기 연결 ID를 사이트 설정에 넣어야 그 계정만 글과 사진을 열 수 있습니다. 연결 ID는 이 사이트 안에서 내 로그인 계정을 가리키는 값이고 비밀번호가 아닙니다. 확인하는 것만으로는 소유자가 되지 않고 자료가 공개되지도 않습니다.

알아둘 점: 원보드는 Sites가 서버에 넘겨 주는 로그인 사용자 식별값으로 소유자를 가려냅니다. 이 값은 Sites 공식 문서의 로그인 항목에 나와 있지 않고, 만든 사람의 계정에서 동작하는 것만 확인했습니다. 다른 계정에서 값이 어떻게 나오는지는 확인되지 않았습니다.

막혔을 때:

- “계정을 확인하지 못했어요. 연결 상태를 확인하고 다시 시도해주세요.”가 나오고 다시 눌러도 같으면, 내 계정에서는 이 식별값이 전달되지 않는 것일 수 있습니다. 이 경우 지금 방식으로는 설치를 끝낼 수 없습니다. [문제 알리기](#문제-알리기)로 꼭 알려 주세요.
- ChatGPT가 환경 값을 직접 저장하지 못한다고 하면 내가 직접 넣을 수 있습니다. ChatGPT에서 **Sites**를 열고 해당 사이트의 **More actions > Settings**에서 이름 `WONBOARD_OWNER_ID`, 값에 연결 ID를 넣어 저장한 뒤, ChatGPT에 「저장한 버전을 다시 배포해 주세요」라고 요청하세요. 한국어 화면에서는 메뉴 이름이 다를 수 있습니다.

### 6. ChatGPT가 다시 배포하기

환경 값은 다시 배포해야 적용됩니다. ChatGPT가 앞서 저장한 버전을 다시 배포하고, 끝났다고 알려 줍니다.

막혔을 때: ChatGPT가 다시 배포하지 않고 끝냈다면 「환경 값을 적용하려면 저장한 버전을 다시 배포해 주세요」라고 요청하세요.

### 7. 설치 상태 확인하고 시작하기

사이트로 돌아가 “설치 상태 다시 확인”을 누릅니다.

보게 될 화면: 내 이름과 함께 “시작 전에 확인해주세요.”라는 안내가 나오고, 글과 사진이 어디에 저장되고 언제 공개되는지를 설명하는 항목 네 개가 보입니다. 내용을 읽고 “자료가 저장되는 곳과 사진이 공개되는 시점을 이해했습니다.”에 표시한 뒤 “내 글쓰기 공간 열기”를 누르면 글 목록과 편집기가 열립니다. 여기까지 오면 설치가 끝난 것입니다.

막혔을 때:

- 여전히 “원보드 설치가 아직 끝나지 않았어요.”가 보이면 환경 값이 적용되지 않은 것입니다. ChatGPT에 환경 값 이름이 `WONBOARD_OWNER_ID`가 맞는지, 다시 배포가 끝났는지 확인해 달라고 하세요.
- “다른 계정의 글쓰기 공간입니다. 이 Site를 설치한 계정으로 로그인해주세요.”가 보이면 저장한 연결 ID와 지금 로그인한 계정이 다릅니다. 5단계에서 연결 ID를 확인한 계정으로 로그인했는지, 값을 일부만 복사하지 않았는지 확인하세요.

## 설치한 뒤

- **사진 공개와 사이트 접근 범위는 따로입니다.** 원보드에서 사진을 공개로 등록해도, 사이트 접근 범위가 처음 상태 그대로면 다른 사람에게는 사진이 보이지 않습니다. 게시판에 붙인 사진이 남에게 보이게 하려면 Sites의 공유 설정에서 사이트 접근 범위를 넓혀야 합니다. 범위를 넓혀도 글 목록·초안·원본 사진은 소유자 계정으로만 열립니다. 만든 사람의 사이트에서 로그인하지 않은 요청이 거절되는 것까지는 확인했고, 다른 실제 계정으로 로그인했을 때 막히는지는 아직 확인하지 못했습니다.
- **ZIP 백업을 따로 보관하세요.** Sites는 베타이고 계정의 한도에 닿으면 공개 사진이 표시되지 않을 수 있습니다.
- **편집자 초대는 신중하게.** 워크스페이스에서 사이트 편집자로 초대한 사람은 초안을 포함한 실제 데이터를 읽을 수 있습니다. [공동 편집 안내](https://learn.chatgpt.com/docs/sites?surface=app#collaborate-on-a-site)
- **저장 위치와 밖으로 나가는 것**은 [개인정보·저장 안내](https://jiwonschol.github.io/wonboard/privacy.html)에 판별로 적혀 있습니다. 편집 화면의 「더 보기」에서도 열 수 있습니다.
- **새 버전으로 올리기**는 [새 버전으로 올리기](#새-버전으로-올리기)를 따르세요. 올리기 전에 ZIP 백업을 먼저 받습니다.

## 새 버전으로 올리기

이미 설치한 원보드 사이트를 새 버전으로 바꾸는 방법입니다. 새 사이트를 만드는 것이 아니라, 지금 쓰는 사이트에 새 버전의 코드를 배포합니다.

**실제 사이트에서 해 본 적이 없는 절차입니다.** 아래 내용은 [Sites 공식 문서](https://learn.chatgpt.com/docs/sites?surface=app)(2026-10-08 확인)와 원보드 코드를 근거로 적었습니다. 원보드의 Sites 설정도 공식 문서를 기준으로 만든 것이라 처음 시험 설치 때 쓰인 설정과 대조하지 못했습니다. Sites는 공개 베타라 절차가 바뀔 수 있습니다. 해 보고 막히거나 안내와 다르면 [문제 알리기](#문제-알리기)로 알려 주세요.

### 새 버전이 나왔는지 알기

가장 최근 버전의 이름(태그, `v`로 시작합니다)은 [소개 페이지](https://jiwonschol.github.io/wonboard/)의 설치 방법에 나옵니다. 지금까지의 버전은 [태그 목록](https://github.com/jiwonschol/wonboard/tags)에서 볼 수 있습니다. 내 사이트의 버전은 원보드 화면 위쪽 막대와 「더 보기」에 나오는 버전 번호로 확인합니다. 설치 문장이 태그를 가리키게 된 뒤에 설치했다면, 두 번호가 같을 때 올릴 것이 없습니다.

**설치 문장이 태그를 가리키기 전에 설치한 사이트는 예외입니다.** 그때의 설치 문장은 그날의 main 브랜치 코드를 가져왔고, 버전 번호는 여러 커밋 동안 `0.1.0-beta.1`로 같았습니다. 그래서 번호가 같아도 첫 태그(버전 `0.1.0-beta.1`)의 코드와 다를 수 있습니다. 설치 문장의 「저장소」 줄에 「main 브랜치」라고 적혀 있던 때 설치했다면, 번호가 같아도 아래 절차로 소개 페이지에 나온 버전을 한 번 올리세요. Sites는 로컬 프로젝트로 저장한 버전을 빌드에 쓴 Git 커밋과 연결해 두므로([Understand projects, versions, and deployments](https://learn.chatgpt.com/docs/sites?surface=app#understand-projects-versions-and-deployments)), ChatGPT에 「지금 배포된 버전이 어느 원보드 커밋으로 만든 것인지 알려 주세요」라고 물어 확인할 수도 있습니다.

### 1. 올리기 전에 ZIP 백업 받기

원보드의 「PC 저장」에서 백업(.zip)을 받아 내 컴퓨터에 보관합니다. 올리는 도중 문제가 생겨도 이 백업을 「백업 가져오기」로 열면 글과 사진을 되찾을 수 있습니다.

Sites 공식 문서는 이전 버전 복원을 편집자는 할 수 없는 소유자의 작업으로 적을 뿐, 복원할 때 DB의 글과 사진까지 이전 상태로 돌아가는지는 적지 않습니다. 이전 버전 복원에 기대지 말고 백업을 먼저 받으세요.

### 2. ChatGPT에 올리기 요청하기

원보드를 설치했던 ChatGPT 대화나 새 대화에 아래 요청을 보냅니다. 보내기 전에 `<내 사이트 주소>`를 내 원보드 사이트 주소로, `<새 버전>`을 올릴 버전 이름으로 바꿉니다(두 곳).

```text
@Sites 이미 배포한 내 원보드(Wonboard) 사이트를 새 버전으로 올려 주세요. 새 사이트를 만들지 마세요.

- 올릴 사이트: <내 사이트 주소>
- 가져올 코드: https://github.com/jiwonschol/wonboard 저장소의 태그 <새 버전>. 저장소를 직접 가져올 수 없으면 멈추고, 제가 https://github.com/jiwonschol/wonboard/archive/refs/tags/<새 버전>.zip 파일을 첨부하도록 안내해 주세요.

1. 위 사이트의 기존 Sites 프로젝트에 새 버전을 저장해 주세요. 태그의 `.openai/hosting.json`에는 프로젝트 ID가 없으니, 기존 사이트의 프로젝트 ID를 `project_id`로 넣어 연결해 주세요. D1 `DB`, R2 `MEDIA` 연결은 그대로 쓰고, 새 프로젝트나 새 DB·파일 저장소를 만들지 마세요.
2. 설치 때처럼 `pnpm install --frozen-lockfile`과 `pnpm build:sites`로 빌드해 주세요. 1번의 `project_id` 말고는 코드와 설정을 고치지 마세요.
3. 이 사이트의 DB에 이미 적용된 마이그레이션과 새 버전의 `drizzle` 폴더를 비교해, 아직 적용되지 않은 것만 적용 대상으로 삼아 주세요. `0000_sites-initial.sql`은 빈 DB 전용이라 이 사이트에 다시 적용하면 안 됩니다. 이미 적용된 파일과 새 버전의 같은 이름 파일 내용이 다르면 배포하지 말고 멈춰 주세요.
4. 환경 값 `WONBOARD_OWNER_ID`와 사이트 접근 범위는 바꾸지 마세요.
5. 배포하기 전에 저장한 버전과 적용할 마이그레이션 목록(없으면 없다고)을 보여 주고, 제가 확인한 뒤에 배포해 주세요.
6. 배포가 끝나면 사이트 주소가 그대로인지와 배포한 버전을 만든 원보드 태그를 알려 주세요.
```

보게 될 화면: ChatGPT가 코드를 가져와 빌드하고, 저장한 버전과 적용할 마이그레이션 목록을 보여 준 뒤 배포해도 되는지 묻습니다. 목록을 확인하고 배포를 승인하세요.

막혔을 때:

- ChatGPT가 새 사이트를 만들겠다고 하거나 새 주소를 알려 주면 진행하지 마세요. 새 사이트에는 내 글과 사진이 없습니다. 「새 사이트를 만들지 말고 <내 사이트 주소>의 기존 프로젝트에 저장해 주세요」라고 다시 요청하세요.
- 적용할 마이그레이션 목록에 `0000_sites-initial.sql`이 들어 있으면 배포를 승인하지 마세요. 「이 사이트는 이미 쓰고 있는 DB입니다. 초기 마이그레이션을 빼고 아직 적용되지 않은 것만 보여 주세요」라고 요청하세요.
- 빌드나 배포가 실패하면 ChatGPT가 알려 준 오류를 그대로 복사해 [문제 알리기](#문제-알리기)로 보내 주세요. ChatGPT가 오류를 피하려고 코드나 설정을 바꾸게 하지 마세요.

### 3. 올린 뒤 확인하기

사이트를 열어 로그인하고 다음을 확인합니다.

- 위쪽 막대나 「더 보기」의 버전 번호가 새 버전으로 바뀌었다.
- 글 목록에 전에 쓴 글이 그대로 있고, 글을 열면 사진이 보인다.
- 「공유하기」로 공개했던 사진의 주소를 새 탭에서 열면 그대로 열린다.

하나라도 다르면 더 쓰기 전에 [문제 알리기](#문제-알리기)로 알려 주세요. 1단계의 백업은 문제가 풀릴 때까지 지우지 마세요.

### DB 변경이 있는 버전

새 버전이 글과 사진을 저장하는 DB 구조를 바꾸면, 그 버전의 저장소 `drizzle` 폴더에 새 SQL 파일(마이그레이션)이 번호를 이어 추가됩니다. 설치 때 쓴 것은 `0000_sites-initial.sql` 하나입니다. DB 변경이 없는 버전은 적용할 마이그레이션이 없고 화면과 서버 코드만 바뀝니다.

DB 변경이 있는 버전에서 달라지는 것:

- 배포할 때 새 마이그레이션이 내 사이트의 DB에 적용됩니다. 2단계 요청의 5번에서 ChatGPT가 보여 주는 목록이 그것입니다. Sites 공식 문서도 로컬 프로젝트로 만든 사이트는 공유 전에 Codex 검토 화면에서 DB 마이그레이션을 검토하라고 안내합니다([Review before you share](https://learn.chatgpt.com/docs/sites?surface=app#review-before-you-share)).
- 적용된 마이그레이션은 되돌리지 않는 변경으로 생각하세요. 배포 뒤 이전 버전을 복원해도 DB 구조가 함께 돌아간다는 공식 안내는 없습니다. 이전 버전으로 돌아가야 한다면 1단계의 ZIP 백업이 기준입니다.
- 이미 적용된 마이그레이션과 `0000_sites-initial.sql`은 다시 적용하지 않습니다. 빈 DB 전용인 초기 마이그레이션을 쓰고 있는 DB에 다시 적용하면 안 됩니다.
- Sites가 새 마이그레이션을 배포 때 자동으로 적용하는지, ChatGPT가 따로 적용하는지는 공식 문서에 적혀 있지 않고 실제로 확인한 적도 없습니다.

만든 사람이 2026년 9월에 처음 시험 설치한 사이트처럼 지금 설치 문장보다 먼저 만든 구조의 사이트는 이 절차가 아니라 [기존 설치 업그레이드](./sites-deployment.md#기존-설치-업그레이드)를 따릅니다.

### 글·사진·공개 주소가 유지되는 이유

새 버전으로 올려도 다음은 바뀌지 않습니다. 다만 아래 근거는 공식 문서와 코드에서 따온 것이고, 실제 사이트에서 올려 보고 확인한 것은 아닙니다.

| 유지되는 것 | 근거 |
| --- | --- |
| 사이트 주소 | 공식 문서에서 사이트는 다시 열어 고치고 새 버전을 저장·배포하는 하나의 지속되는 결과물입니다([Understand projects, versions, and deployments](https://learn.chatgpt.com/docs/sites?surface=app#understand-projects-versions-and-deployments)). 주소는 소유자가 설정에서 바꿀 때 바뀌고, 그 변경은 배포와 별개입니다([Change a Site URL](https://learn.chatgpt.com/docs/sites?surface=app#change-a-site-url)). 같은 사이트에 배포하면 주소는 그대로입니다. |
| 글과 사진 | 원보드의 글은 사이트에 연결된 D1 `DB`에, 사진은 R2 `MEDIA`에 저장됩니다. 공식 문서는 D1·R2를 방문 사이에 남는 저장소로 설명하고, 사이트와 저장소의 연결을 `.openai/hosting.json`의 프로젝트 ID와 연결 이름으로 정합니다. 새 버전도 같은 연결 이름 `DB`·`MEDIA`를 쓰므로, 기존 프로젝트에 배포하면 같은 저장소를 씁니다. 지금까지 나온 기존 설치용 업그레이드 SQL도 기존 공개 주소와 자료를 지우지 않고 참조 추적을 더하도록 만들었고, 로컬 시험이 그 적용과 자료 보존을 검증합니다([Sites 배포 설정과 DB 경로](./sites-deployment.md#기존-설치-업그레이드)). |
| 공개한 사진 주소 | 공개 사진 주소는 `사이트 주소/media/공개 ID` 모양이고, 공개 ID는 DB에 저장됩니다(`apps/server/src/sites/worker.ts`). 사이트 주소와 DB가 그대로면 같은 주소로 같은 사진이 열립니다. |
| 소유자 연결 | `WONBOARD_OWNER_ID`는 코드가 아니라 사이트 설정의 환경 값에 있습니다([Configure runtime environment values](https://learn.chatgpt.com/docs/sites?surface=app#configure-runtime-environment-values)). 2단계 요청은 이 값을 바꾸지 않게 합니다. |

새 사이트를 만들어 배포하면 이 중 아무것도 이어지지 않습니다. 주소도, DB도, 파일 저장소도 새로 생깁니다. 그래서 2단계 요청은 새 사이트를 만들지 말라고 먼저 적습니다.

## 그만 쓰는 방법

1. 원보드에서 중요한 글과 사진을 ZIP으로 백업합니다.
2. 잠시 닫아 두기만 하려면 Sites의 공유 설정에서 접근 범위를 나 또는 고른 사람만 열 수 있게 좁힙니다. 사이트와 자료는 남습니다.
3. 완전히 지우려면 ChatGPT에서 **Sites**를 열어 해당 사이트를 찾고 **Delete site**를 고른 뒤, 안내에 따라 사이트 이름(slug)을 입력하고 **Permanently delete**를 누릅니다. [공식 삭제 안내](https://learn.chatgpt.com/docs/sites?surface=app#take-down-or-delete-a-site)

삭제한 사이트는 되살릴 수 없습니다. 사이트에 연결된 저장소의 자료가 어디까지 지워지는지는 삭제 화면의 안내를 확인하세요. 이미 게시판에 붙인 사진을 다른 사람이 내려받은 사본은 회수되지 않습니다. 원보드에는 가입이 없으므로 따로 탈퇴할 계정도 없습니다.

## 확인된 것과 확인되지 않은 것

| 내용 | 상태 |
| --- | --- |
| 만든 사람의 계정에서 설치, 로그인, 소유자 연결, 글·사진 저장 | 한 번 확인 |
| 다른 계정에서의 설치 전체 | 확인되지 않음 |
| ChatGPT가 저장소 주소만으로 코드를 가져오는지 | 확인되지 않음(확인된 것은 ZIP 첨부) |
| 설치 문장이 정한 태그의 코드를 ChatGPT가 가져오는지 | 확인되지 않음 |
| 새 버전으로 올리기(글·사진·공개 주소 유지 포함) | 확인되지 않음(공식 문서와 코드로만 근거를 댐) |
| 다른 계정에서 연결 ID가 나오는지 | 확인되지 않음 |
| 설치 링크, 템플릿 복제, 문장이 미리 채워진 ChatGPT 링크 | 공식 문서에 없어 쓰지 않음(2026-10-06 확인) |

## 문제 알리기

[GitHub Issues](https://github.com/jiwonschol/wonboard/issues)에 어느 단계에서 막혔는지, 화면에 나온 안내, ChatGPT가 알려 준 오류를 적어 주세요. 연결 ID, 이메일, 사이트 주소처럼 나를 가리키는 값은 지우고 올려 주세요.
